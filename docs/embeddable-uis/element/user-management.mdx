Let the admins of your application invite users and assign roles from inside your application with the User Management element. This page is for developers and admins who configure the element in the Permit dashboard. It explains the permission models, the preview, and pending invitations, and links to the embedding steps.

![User Management element embedded in an application, listing members with their roles and an invite field with a Send Invite button](/img/elements/user-management-full.png)

## What users can do in the element

Users see and do different things in the element depending on their permission level. See [Permission levels](/embeddable-uis/permission-levels).

- Invite a user by email with a role, using **Send Invite**
- Change the roles of existing users
- See invited users who wait for approval
- Review access requests from a connected [Access Request element](/embeddable-uis/element/access-request)

## Choose a permission model \{#understanding-the-element}

When you create the element, you choose one of two permission models.

### RBAC: environment roles \{#role-based-access-control-rbac-roles}

With role-based access control (RBAC), the element manages the roles users hold across a tenant. You drag your roles into the element's permission levels. The level a role is in sets what users with that role can do in this element, for example whether they can assign roles to others.

### ReBAC: resource roles \{#relationship-based-access-control-rebac-resource-roles}

With relationship-based access control (ReBAC), the element manages roles on individual resource instances. You select the resource the element manages, and then drag the resource roles defined for that resource into the permission levels. Users of the element then assign roles on specific instances of that resource.

## Preview the element \{#interacting-with-the-ui}

The **End User Preview** on the right of the element form shows the element for a selected permission level and tenant. Use it to confirm your permission levels before you embed the element. See [Preview an element](/embeddable-uis/user-preview).

With the ReBAC model, the preview also lets you switch between instances of the selected resource, to see the roles on each instance.

## Pending user invitations \{#pending-user-invitations}

When **Email Notification** or **Webhook Notification** is turned on for the element, inviting a user sends an email or a webhook. The invited user appears in the element as pending until the invite is approved. After approval, Permit creates the user with the role from the invite.

- To send invite emails and approve invites with the SDK, see [Email Configuration and Templates](/embeddable-uis/email-configuration-and-templates).
- To receive invite events in your backend, see [Configure webhooks](/embeddable-uis/webhooks).
