Run the Permit.io and SuperTokens example app to see how a Next.js application syncs [SuperTokens](https://supertokens.com) users into Permit at sign-up and checks their permissions. This page is for developers who use SuperTokens and want a working reference before they write their own handoff code.

For the general integration steps that apply to any provider, see [Connect your authentication](/authentication/your-authentication).

## What the example app does

The [permit-x-supertokens repository](https://github.com/filipermit/permit-x-supertokens) is a Next.js app with these parts:

| File | What it does |
|---|---|
| `config/backendConfig.js` | Configures SuperTokens email and password sign-up and third-party sign-in. After a new user signs up, the code syncs the user to Permit with the SuperTokens user ID as the user key. It assigns the `Friend` role to `@supertokens.com` and `@permit.io` email addresses and the `Stranger` role to every other address, in a tenant with the key `SuperTokens`. |
| `pages/api/auth/permit.js` | Verifies the SuperTokens session, then calls `permit.check()` with the session's user ID, the requested action, and the resource type in the `SuperTokens` tenant. Returns HTTP 200 when Permit allows the action and HTTP 403 when Permit denies it. |
| `pages/demo.js` | Checks the `view-personal-info` and `view-gpg-key` actions on the `card` resource and shows or hides content based on the result. |

The app connects to the SuperTokens demo core at `https://try.supertokens.com` and to a policy decision point (PDP) at `http://localhost:7766`.

## Prerequisites

- A Permit.io account. Complete the [Quickstart](/quickstart) if you don't have one.
- Your environment API key. See [Get your API key](/overview/get-api-key).
- Node.js and npm, to run the app.
- Docker, to run the PDP.

## Create the policy the app expects

In the Permit dashboard, in the environment that matches your API key:

1. Create a tenant with the key `SuperTokens`.
2. Create a resource with the key `card` and the actions `view-personal-info` and `view-gpg-key`.
3. Create the roles `Friend` and `Stranger`. Role keys are case-sensitive.
4. In the Policy Editor, allow the actions you want each role to have.

## Run the example app

1. Clone the [permit-x-supertokens repository](https://github.com/filipermit/permit-x-supertokens) and open the repository folder.

2. Set your Permit environment API key in the `PERMIT_IO_KEY` environment variable, for example in a `.env.local` file in the repository root. The app reads the key from `process.env.PERMIT_IO_KEY`.

3. Install the project dependencies:

   ```
   npm install
   ```

4. Start the app:

   ```
   npm run dev
   ```

   The app runs at `http://localhost:3000`.

5. In a separate terminal, run the PDP. Replace `<YOUR_PERMIT_API_KEY>` with your environment API key:

   ```
   docker run -p 7766:7000 --env PDP_DEBUG=True --env PDP_API_KEY=<YOUR_PERMIT_API_KEY> permitio/pdp-v2:latest
   ```

   The command maps port 7000 in the container to port 7766 on your machine, where the app sends its permission checks.

## Verify the integration

1. Open `http://localhost:3000` and sign up with a new user.
2. In the Permit dashboard, open **Directory** and select the `SuperTokens` tenant. The user appears with the SuperTokens user ID as its key and the `Friend` or `Stranger` role.
3. Open `http://localhost:3000/demo`. The content for each action shows only if the user's role allows that action on `card`. The terminal that runs the app logs `<user ID> is PERMITTED to <action> on card` or `<user ID> is NOT PERMITTED to <action> on card` for each check.

## Adapt the example to your application

The example uses an early version of the Permit Node.js SDK (`permitio` 0.0.5). The `permit.write()` wrapper and the `roles` field inside `syncUser()` are not part of the current SDK. When you copy the pattern into your application:

- Sync the user with `permit.api.syncUser()`, as shown in [Sync users](/how-to/sync-users).
- Assign the role in a separate call, as shown in the [Node.js `assignRole` reference](/sdk/nodejs/role/assign-role).
- Run the PDP image and options from [Deploy the PDP to production](/how-to/deploy/deploy-to-production).
