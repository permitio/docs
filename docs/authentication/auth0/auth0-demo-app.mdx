Clone and run a Next.js to-do app that signs users in with Auth0 and checks every task request with Permit.io. This page is for developers who want a working example before they add Permit to their own Auth0 app. The app is based on the [Auth0 Next.js quickstart](https://auth0.com/docs/quickstart/webapp/nextjs/interactive). You don't need Next.js experience to run it.

To add the same integration to your own application, follow [Auth0 and Permit integration](/authentication/auth0/permit-integration).

## Prerequisites

- An Auth0 account with an application configured for the Next.js SDK.
- A [Permit.io account](https://app.permit.io/) and your environment API key. See [Get your API key](/overview/get-api-key).
- Node.js, installed [locally](https://nodejs.org/en/download) or in a remote development environment.
- Git.

## 1. Create the policy in Permit \{#12-create-the-right-resources-in-permit}

The demo app checks the `task` resource with the HTTP method of each request as the action. Create this policy in the [Permit dashboard](https://app.permit.io/policy-editor), with the [Permit API](https://api.permit.io/v2/redoc#tag/Roles/operation/create_role), or with an SDK ([Python](/sdk/python/usage-example/#create-a-role), [Node.js](/sdk/nodejs/quickstart-nodejs#creating-a-new-role-with-permissions), or [another SDK](/sdk/sdks-overview)):

1. Create a resource with the key `task` and the actions `get`, `post`, and `delete`.
2. Create the roles `admin`, `manager`, and `viewer`. Use lowercase keys. Role keys are case-sensitive and must match the role names in Auth0.
3. Assign permissions:

| Role | `get` | `post` | `delete` |
|---|---|---|---|
| `admin` | Allowed | Allowed | Allowed |
| `manager` | Allowed | Allowed | Denied |
| `viewer` | Allowed | Denied | Denied |

You can also assign permissions with the [assign permissions API](https://api.permit.io/v2/redoc#tag/Roles/operation/assign_permissions_to_role).

## 2. Run the demo application \{#2-run-the-demo-application}

1. Clone the repository and check out the `auth0-integration` branch. Run `git checkout auth0-integration` from inside the `permit-next-todo-starter` folder:

```bash
git clone https://github.com/permitio/permit-next-todo-starter
git checkout auth0-integration
```

2. Create a `.env.local` file in the repository root. The repository includes `.env.local.example` as a template. Add your Auth0 values. To get them in this format, open the [Auth0 Next.js SDK configuration](https://auth0.com/docs/quickstart/webapp/nextjs/interactive#configure-the-sdk) while signed in to Auth0:

```bash
AUTH0_SECRET='<auth0_secret>'
AUTH0_BASE_URL='http://localhost:3000'
AUTH0_ISSUER_BASE_URL='<auth0_issuer_base_url>'
AUTH0_CLIENT_ID=<auth0_client_id>
AUTH0_CLIENT_SECRET='<auth0_client_secret>'
```

3. Add your Permit environment API key to the same file. Copy the key from the [Projects page](https://app.permit.io/projects): click the three dots on your environment and select **Copy API Key**.

![Permit Projects page with the Copy API Key option in the environment menu](/img/onboarding/secret-key-1.png)

```bash
PERMIT_API_KEY=<permit_api_key>
```

The demo code reads the key from `PERMIT_SDK_TOKEN`, as the `.env.local.example` file shows. Use `PERMIT_SDK_TOKEN` as the variable name in `.env.local`.

4. Install the dependencies with `npm install`, then start the app with `npm run dev`. The app runs at `http://localhost:3000`, the value of `AUTH0_BASE_URL`.

5. [Add Auth0 roles to the user's tokens](/authentication/auth0/permit-integration#31-sync-auth0-with-permit) with an Auth0 Action. The demo reads roles from the `my_app_name/roles` claim.

## 3. How the demo app works \{#3-how-it-works}

### Auth0 authentication in the demo app \{#31-auth0}

The Auth0 SDK identifies the user on both sides of the app.

On the frontend, `_app.tsx` wraps the app in the Auth0 `UserProvider`, and `index.tsx` reads the signed-in user's information with `useUser`:

```tsx
// index.tsx
//...
const { user, isLoading } = useUser();
//...
```

```tsx
// _app.tsx
//...
<UserProvider>
  <Component {...pageProps} />
</UserProvider>
//...
```

On the backend, `pages/api/auth/[...auth0].ts` handles all Auth0 routes. Any API route can read the Auth0 session with `getSession`, as `pages/api/tasks.ts` does:

```ts
// pages/api/auth/[...auth0].ts
import { handleAuth } from "@auth0/nextjs-auth0";

export default handleAuth();
```

```ts
// pages/api/tasks.ts
import { getSession } from "@auth0/nextjs-auth0";
//...
export default async function handler(req: NextApiRequest, res: NextApiResponse) {
	const session = await getSession(req, res); // if the user is not logged in, session will be null
	if (!session?.user) {
    res.status(401).json({ message: 'unauthorized' });
    return;
  }
}
//...
```

### Permit authorization in the demo app \{#32-permit}

Authorization runs only on the backend. `pages/api/tasks.ts` creates the Permit client and checks each task request before it runs. The user key is the Auth0 user ID, the action is the HTTP method in lowercase, and the resource is `task`:

```ts
// pages/api/tasks.ts
import { Permit } from "permitio";

export const permit = new Permit({
  pdp: "https://cloudpdp.api.permit.io",
  token: process.env.PERMIT_SDK_TOKEN,
});
export default withApiAuthRequired(async function handler(
  req: NextApiRequest,
  res: NextApiResponse<Task | Task[] | Response>
) {
  // Auth0 is checking if the user is logged in (who the user is)
  const session = await getSession(req, res);
  if (!session?.user) {
    res.status(401).json({ message: "unauthorized" });
    return;
  }
  // Permit is checking if the user has the right permissions (what the user can do)
  const isAllowedForOperation = await permit.check(
    (session?.user?.sub as string) || "", // the user identifier (Permit user id / or Permit user key, in this example we set the Auth0 user id as the key)
    req.method?.toLowerCase() as string, // the action (can be: get, post, delete)
    "task" // our resource key
  );
  if (!isAllowedForOperation) {
    res.status(403).json({ message: "forbidden" });
    return;
  }
  //... handle the request
});
```

The route returns HTTP 401 when there is no Auth0 session and HTTP 403 when Permit denies the action.

## 4. How the demo app syncs users and roles \{#4-the-integration}

Permit can only match a user to roles after the user exists in Permit. The demo app syncs users right after login.

### Sync Auth0 with Permit \{#41-sync-auth0-with-permit}

The Auth0 login handler sends every user to the `/postLogin` page after login:

```ts
// pages/api/auth/[...auth0].ts
import { handleAuth, handleLogin } from "@auth0/nextjs-auth0";

export default handleAuth({
  async login(req, res) {
    await handleLogin(req, res, {
      returnTo: "/postLogin",
    });
  },
});
```

The `/postLogin` page syncs the user to Permit in `getServerSideProps`, with the Auth0 user ID as the user key:

```tsx
// pages/postLogin/index.tsx
export async function getServerSideProps({ req, res }: any) {
  const session = await getSession(req, res);
  const permitUserObj = {
    email: session?.user?.email,
    key: session?.user?.sub,
    first_name: session?.user?.name,
  };
  const permitUser = await permit.api.syncUser(permitUserObj);
  //... the sync role logic
}
```

Next, the page reads the roles from the `my_app_name/roles` claim, which the [Auth0 Action in the integration guide](/authentication/auth0/permit-integration#31-sync-auth0-with-permit) adds, and assigns each role in the `default` tenant. The block ends the same `getServerSideProps` function and redirects the user to the home page:

```tsx
    if (session?.user['my_app_name/roles']) {
        session?.user['my_app_name/roles'].map(async (roleKey: string) => {
            console.log(roleKey);
            const roleToAssign = {
                role: roleKey,
                user: permitUserObj.key,
                tenant: 'default'
            }
            const assignedRole = await permit.api.roleAssignments.assign(roleToAssign);
            console.log(assignedRole);
        });
    }
    redirect(res, 302, '/');
}
```

Role keys must match exactly in Auth0 and Permit, because keys are case-sensitive. The full page, including the check that skips users who already exist in Permit, is in [pages/postLogin/index.tsx on GitHub](https://github.com/permitio/permit-next-todo-starter/blob/auth0-integration/pages/postLogin/index.tsx).

## 5. Verify the demo \{#verify-the-demo}

1. In Auth0, create a user and assign the `manager` role.
2. Open `http://localhost:3000` and sign in with that user.
3. Add a task. The task appears in the list.
4. Delete a task. The request fails, because `manager` can't `delete` tasks. The API returns HTTP 403.
5. In the Permit dashboard, open **Directory** and assign the `admin` role to the user. Delete the task again. The delete succeeds.
