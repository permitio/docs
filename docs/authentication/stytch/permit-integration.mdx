Add [Stytch](https://stytch.com) sign-in to a Next.js app (Pages Router), then connect it to Permit.io authorization at the handoff point: after Stytch authenticates a session, your backend creates a Permit tenant for the user, syncs the user, and assigns a role. This tutorial is for developers who use Stytch Consumer authentication and want role-based access control (RBAC) from Permit. It shows one way to set up Stytch. Stytch also has example apps for other languages and frameworks.

## What you build

- Email magic link and Google OAuth sign-in with the Stytch Next.js SDK.
- A redirect page that completes the Stytch authentication.
- A protected frontend page and a protected server-side route.
- A handoff point that creates a Permit tenant, syncs the Stytch user, and assigns the `AccountOwner` role.
- A `permit.check()` call that decides whether the user can `view-all` on an `Account` resource.

## Prerequisites

- A Stytch account with a Consumer project. See the [Stytch Next.js quickstart](https://stytch.com/docs/guides/quickstarts/nextjs#before-you-start).
- A [Permit.io account](https://app.permit.io/) and your environment API key. See [Get your API key](/overview/get-api-key).
- A Next.js project that uses the Pages Router. To create one, run `npx create-next-app@latest`.
- The Permit Node.js SDK: `npm install permitio`.

## 1. Install the Stytch SDKs and set your API keys \{#step-1-install-stytch-sdks-and-configure-your-api-keys}

Install the Stytch frontend SDKs and the Stytch backend Node.js SDK:

```bash
npm install @stytch/nextjs @stytch/vanilla-js stytch --save
```

Add your Stytch project's API keys to your application's environment variables, for example in `.env.local`. Copy the values from the Stytch dashboard:

```bash
STYTCH_PROJECT_ENV=test
STYTCH_PROJECT_ID="YOUR_STYTCH_PROJECT_ID"
NEXT_PUBLIC_STYTCH_PUBLIC_TOKEN="YOUR_STYTCH_PUBLIC_TOKEN"
STYTCH_SECRET="YOUR_STYTCH_SECRET"
```

## 2. Wrap your application in a StytchProvider \{#step-2-wrap-your-application-in-a-stytchprovider}

In `pages/_app.js`, create the Stytch client and wrap the app in `StytchProvider`, so every page can use the Stytch frontend SDK:

```javascript
import { StytchProvider, createStytchUIClient } from "@stytch/nextjs";
import Head from "next/head";

const stytch = createStytchUIClient(process.env.NEXT_PUBLIC_STYTCH_PUBLIC_TOKEN);

export default function App({ Component, pageProps }) {
  return (
    <>
      <Head>{/* Truncated */}</Head>
      <StytchProvider stytch={stytch}>
        <Component {...pageProps} />
      </StytchProvider>
    </>
  );
}
```

## 3. Add the Stytch login component \{#step-3-add-a-stytchlogin-component}

Create a `Login` component. The `products` array sets the sign-in methods. This example offers email magic links and Google OAuth:

```javascript
import { StytchLogin } from "@stytch/nextjs";
import { Products } from "@stytch/vanilla-js";

const Login = () => {
  const REDIRECT_URL = "SEE_STEP_5";

  const config = {
    products: [Products.emailMagicLinks, Products.oauth],
    emailMagicLinksOptions: {
      loginRedirectURL: REDIRECT_URL,
      loginExpirationMinutes: 60,
      signupRedirectURL: REDIRECT_URL,
      signupExpirationMinutes: 60,
    },
    oauthOptions: {
      providers: [{ type: "google" }],
      loginRedirectURL: REDIRECT_URL,
      signupRedirectURL: REDIRECT_URL,
    },
  };

  return <StytchLogin config={config} styles={{}} />;
};
```

Replace `SEE_STEP_5` with the full URL of the redirect page you create in step 4, for example `http://localhost:3000/authenticate` if you name the page `pages/authenticate.js`. Stytch sends users to that URL after they click a magic link or finish OAuth. Add the same URL on the [Redirect URLs tab](https://stytch.com/docs/guides/dashboard/redirect-urls) of the Stytch dashboard.

Add the `Login` component to your login page. The page sends users who are already signed in to `/profile`:

```javascript
import { useStytchUser } from "@stytch/nextjs";
import { useRouter } from "next/router";
import { useEffect } from "react";

export default function LoginPage() {
  const { user, isInitialized } = useStytchUser();
  const router = useRouter();

  useEffect(() => {
    if (isInitialized && user) {
      router.replace("/profile");
    }
  }, [user, isInitialized, router]);

  return <Login />;
}
```

## 4. Create the redirect page \{#step-4-handle-redirects-and-complete-the-authentication-flow}

The redirect page reads the `token` and `stytch_token_type` query parameters that Stytch adds to the redirect URL. It authenticates the token with the OAuth method or the magic link method, and creates a session that lasts 60 minutes:

```javascript
import { useRouter } from "next/router";
import { useEffect } from "react";
import { useStytch } from "@stytch/nextjs";

export default function RedirectPage() {
  const router = useRouter();
  const stytch = useStytch();

  useEffect(() => {
    const stytch_token_type = router?.query?.stytch_token_type?.toString();
    const token = router?.query?.token?.toString();

    if (token && stytch_token_type === "oauth") {
      stytch.oauth.authenticate(token, {
        session_duration_minutes: 60,
      });
    } else if (token && stytch_token_type === "magic_links") {
      stytch.magicLinks.authenticate(token, {
        session_duration_minutes: 60,
      });
    }
  }, [router, stytch]);

  return <div>Loading...</div>;
}
```

After Stytch creates the session, the login page from step 3 sends the signed-in user to `/profile`.

## 5. Protect frontend pages \{#step-5-grant-access-to-protected-frontend-content}

The Stytch frontend SDK fills in the session and user objects after sign-in. Use the `useStytchUser` hook to send users who aren't signed in back to the home page:

```javascript
import { useStytchUser, useStytchSession } from "@stytch/nextjs";
import { useEffect } from "react";
import { useRouter } from "next/router";

export default function ProfilePage() {
  const { user, isInitialized } = useStytchUser();
  const router = useRouter();

  useEffect(() => {
    if (isInitialized && !user) {
      router.replace("/");
    }
  }, [user, isInitialized, router]);

  return <div>Profile Page Content</div>;
}
```

## 6. Protect server-side routes \{#step-6-grant-access-to-protected-server-side-routes}

Frontend checks only hide pages. Protect data on the server as well. This `getServerSideProps` function reads the `stytch_session_jwt` cookie, authenticates it with the Stytch backend SDK, and redirects to `/` when the cookie is missing or invalid:

```javascript
import stytch from "stytch";

let client;

const loadStytch = () => {
  if (!client) {
    client = new stytch.Client({
      project_id: process.env.STYTCH_PROJECT_ID || "",
      secret: process.env.STYTCH_SECRET || "",
      env: process.env.STYTCH_PROJECT_ENV === "live" ? stytch.envs.live : stytch.envs.test,
    });
  }
  return client;
};

export async function getServerSideProps({ req }) {
  const redirectRes = {
    redirect: {
      destination: "/",
      permanent: false,
    },
  };

  const sessionJWT = req.cookies["stytch_session_jwt"];

  if (!sessionJWT) {
    return redirectRes;
  }

  const stytchClient = loadStytch();

  try {
    await stytchClient.sessions.authenticateJwt({ session_jwt: sessionJWT });
    return { props: {} };
  } catch (e) {
    return redirectRes;
  }
}
```

When `authenticateJwt()` succeeds, the session is valid and your backend knows the Stytch user ID. This is the handoff point: the place to sync the user into Permit before you show the user any content.

:::tip Why sync users to Permit?
Permit evaluates a permission check against the roles assigned to the user. If the user doesn't exist in Permit, the user has no roles, and every role-based check returns deny.
:::

## 7. Create the policy in Permit \{#permit-pre-sync-setup-guide}

Create the roles, resources, and permissions that your app checks. The [Quickstart](/quickstart) shows how to create a workspace, roles, and resources, and how to assign permissions to roles.

This tutorial uses an `AccountOwner` role (displayed as Account Owner). The role can take the `view-all` action on the account resource, among other actions:

![Permit Policy Editor for the Account Owner role with view-all and other actions checked on Current Account](/ui-videos/authentication/stytch/account-owner-role.png)

## 8. Initialize the Permit SDK \{#importing-and-initializing-the-permit-object}

Run Permit calls on the backend, where your API key stays secret. In the backend file that runs the handoff, import the Permit SDK and create the client:

```javascript
import { Permit } from "permitio";

const permit = new Permit({
  // The Environment API Key
  token: process.env.PERMIT_API_KEY,
  // The URL for the deployed PDP. Usually runs on port 7766.
  pdp: process.env.PERMIT_PDP_HOSTNAME,
});
```

| Environment variable | Value |
|---|---|
| `PERMIT_API_KEY` | Your Permit environment API key |
| `PERMIT_PDP_HOSTNAME` | The URL of your policy decision point (PDP). A container PDP usually listens on port 7766, for example `http://localhost:7766`. For the Cloud PDP, use `https://cloudpdp.api.permit.io`. |

## 9. Sync the user at the handoff point \{#creating-a-handoff-point-check}

Run the Permit calls right after Stytch authenticates the session, before you render protected content.

### Get the Stytch user ID \{#fetching-the-stytch-userid}

Authenticate the session JWT with the Stytch backend SDK, then read the Stytch user ID and email from the session. Permit uses the user ID as the user key:

```javascript
// authenticateJwt throws if the session JWT is invalid
const { session } = await stytchClient.sessions.authenticateJwt({ session_jwt: sessionJWT });
const userId = session.user_id;
const { emails } = await stytchClient.users.get({ user_id: userId });
const userEmail = emails[0]?.email;
// perform all Permit SDK calls here, passing in the userId.
```

### Run the Permit calls after authentication \{#performing-the-authentication-check}

Run the Permit calls only after the session JWT is authenticated. `authenticateJwt()` throws when the JWT is invalid, so place the calls after it inside the `try` block from step 6.

The handoff runs three Permit SDK calls, in this order.

### Create a tenant for the user \{#creating-a-new-tenant}

Each user in this example gets a tenant, so the user's data and role assignments stay separate from other users:

```javascript
const tenantKey = userId; // one tenant per user
await permit.api.tenants.create({
  key: tenantKey,
  name: userEmail,
});
```

### Sync the user \{#adding-a-user-to-the-tenant}

Sync the user to Permit with the Stytch user ID as the key and the user's email:

```javascript
await permit.api.syncUser({
  key: userId,
  email: userEmail,
});
```

### Assign a role to the user \{#assigning-a-role-to-the-user}

Assign the `AccountOwner` role to the user in the user's tenant. The role assignment places the user in the tenant:

```javascript
await permit.api.assignRole({
  role: "AccountOwner",
  tenant: tenantKey,
  user: userId,
});
```

## 10. Verify the integration \{#wrapping-up}

1. Sign in to your app with a new Stytch user.
2. In the Permit dashboard, open **Directory** and select the tenant created for the user. The user appears with the Stytch user ID as its key and the `AccountOwner` role.

![Permit Directory showing a synced user with the AccountOwner role in the user's tenant](/ui-videos/authentication/stytch/user-synced.png)

3. Check a permission in your backend. This check asks whether the user can take the `view-all` action on the `Account` resource in the user's tenant:

```javascript
const isPermitted = await permit.check(userId, "view-all", {
  type: "Account",
  tenant: tenantKey,
});
```

The check returns `true`, because the `AccountOwner` role has `view-all` checked in the Policy Editor.
