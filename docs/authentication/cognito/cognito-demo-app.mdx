Run a demo app that signs users in with Amazon Cognito and uses Permit.io to decide which of two actions each user can take. This page is for developers who want a working example before they add Permit to their own Cognito app. To add the integration to your own application, follow [Cognito and Permit integration](/authentication/cognito/permit-integration).

The demo is based on the [cognito-auth-example repository](https://github.com/sashee/cognito-auth-example) and the article [How to add Cognito login to a website](https://advancedweb.hu/how-to-add-cognito-login-to-a-website/). The full code is in the [permitio/cognito-integration repository](https://github.com/permitio/cognito-integration).

## What the demo app contains

| Folder | What it runs |
|---|---|
| `frontend/` | A vanilla JavaScript page with a **Login** button and two action buttons. It signs the user in with the Cognito hosted login page and calls the backend. |
| `standalone_be/` | An Express server on port 8000. It verifies Cognito tokens, syncs users to Permit, and protects the `POST /say_hello` and `POST /wave_hello` routes with `permit.check()`. |

## Prerequisites

- An AWS account with an Amazon Cognito user pool and an app client. The app client needs the hosted login page enabled, no client secret (the browser exchanges the code without one), and `http://localhost:8181` as an allowed callback URL.
- A [Permit.io account](https://app.permit.io/) and your environment API key. See [Get your API key](/overview/get-api-key).
- Node.js and npm.

## 1. Create the policy in Permit \{#12-create-the-right-resources-and-roles-in-permit}

Create the policy in the [Permit dashboard](https://app.permit.io/policy-editor), with the [Permit API](https://api.permit.io/v2/redoc#tag/Roles/operation/create_role), or with an SDK ([Python](/sdk/python/usage-example/#create-a-role), [Node.js](/sdk/nodejs/quickstart-nodejs#creating-a-new-role-with-permissions), or [another SDK](/sdk/sdks-overview)):

1. Create a resource with the key `hello` and the actions `say` and `wave`.
2. Create the roles `admin` and `viewer`.
3. Allow `say` and `wave` for `admin`. Allow only `wave` for `viewer`. You can also use the [assign permissions API](https://api.permit.io/v2/redoc#tag/Roles/operation/assign_permissions_to_role).

## 2. Run the demo application \{#2-run-the-demo-application}

1. Clone the demo application:

```bash
git clone https://github.com/permitio/cognito-integration
```

2. In the `standalone_be` folder, create a `.env` file based on `.env.example`, with your Cognito and Permit values:

| Variable | Value |
|---|---|
| `USER_POOL_ID` | The ID of your Cognito user pool |
| `CLIENT_ID` | The ID of your Cognito app client |
| `PERMIT_TOKEN` | Your Permit environment API key |

```bash
USER_POOL_ID=<your_user_pool_id>
CLIENT_ID=<your_app_client_id>
PERMIT_TOKEN=<permit_api_key>
```

To copy your Permit API key, open the [Projects page](https://app.permit.io/projects), click the three dots on your environment, and select **Copy API Key**.

![Permit Projects page with the Copy API Key option in the environment menu](/img/onboarding/secret-key-1.png)

3. In the `standalone_be` folder, run `npm install`, then `node index.mjs`. The server logs `Server listening on port 8000`.

4. In the `frontend` folder, copy `config.example.js` to `config.js`. Set `cognitoLoginUrl` to your Cognito domain, in the form `https://<cognito-name>.auth.<region>.amazoncognito.com`, and `clientId` to your app client ID.

5. Serve the `frontend` folder on port 8181 with any static file server, for example `npx http-server -p 8181`. The backend allows browser requests only from `http://localhost:8181`.

## 3. How the demo app works \{#3-how-it-works}

### Cognito sign-in \{#31-cognito}

On the frontend, the **Login** button calls `redirectToLogin`. The function sends the user to the Cognito hosted login page with the authorization code flow and PKCE (Proof Key for Code Exchange):

```js
// app.mjs
const redirectToLogin = async () => {
  const state = await generateNonce();
  const codeVerifier = await generateNonce();
  sessionStorage.setItem(`codeVerifier-${state}`, codeVerifier);
  const codeChallenge = base64URLEncode(await sha256(codeVerifier));
  window.location = `${cognitoLoginUrl}/login?response_type=code&client_id=${clientId}&state=${state}&code_challenge_method=S256&code_challenge=${codeChallenge}&redirect_uri=${window.location.origin}`;
};

//...
```

On the backend, the `GET /api/id` and `GET /api/access` routes verify the ID token and the access token with `CognitoJwtVerifier` from the `aws-jwt-verify` package, and return the token payload:

```js
// standalone_be/index.mjs
// init CognitoJwtVerifier
const verifierIdToken = CognitoJwtVerifier.create({
  userPoolId: userPoolId,
  tokenUse: "id",
  clientId: clientId,
});

app.get("/api/id", async (req, res) => {
  try {
    const payload = await verifierIdToken.verify(
      req.headers.authorization?.split(" ")[1] // the JWT as string
    );
    res.status(200).send(payload);
  } catch {
    res.status(403).send("Token not valid!");
  }
});
//...
```

### Sync users to Permit \{#32-permit-sync-users}

Permit can only match a user to roles after the user exists in Permit. After Cognito redirects back with a `code` query parameter, the frontend exchanges the code for tokens and calls the backend sync route:

```js
// /frontend/app.mjs
//...
if (searchParams.get("code") !== null) {
  //... get the tokens from Cognito
  // After we got the tokens, we need to sync the user info with Permit
  const syncUser = await fetch("http://localhost:8000/api/sync", {
    method: "POST",
    headers: new Headers({ Authorization: `Bearer ${tokens.access_token}` }),
  });
  //...
}
```

The backend `POST /api/sync` route verifies the access token and calls `permit.api.syncUser()` with the Cognito `sub` claim as the user key. The route doesn't assign roles. To assign roles, for example from a mapping between Cognito groups and Permit roles, call `permit.api.assignRole()`. See the [Node.js `assignRole` reference](/sdk/nodejs/role/assign-role/).

```js
// /standalone_be/index.mjs

// init Permit

const permit = new Permit({
  token: permitToken,
  pdp: "https://cloudpdp.api.permit.io",
});

app.post("/api/sync", async (req, res) => {
  // payload is declared outside the try block, so it is still in scope below
  let payload;
  try {
    payload = await verifier.verify(
      req.headers.authorization?.split(" ")[1] // the JWT as string
    );
  } catch (error) {
    res.status(403).send("Token not valid!");
    return;
  }
  // the Cognito access token carries sub, but no name or email claim
  const syncUser = await permit.api.syncUser({
    key: payload.sub,
  });
  // To assign a role here, map Cognito groups to Permit roles and call:
  // await permit.api.users.assignRole({
  //     user: payload.sub,
  //     role: caseSensitiveRoleKey,
  //     tenant: caseSensitiveTenantKey, // if you don't use tenants, use 'default'
  // });
  res.status(200).send(syncUser);
});
```

:::warning The sync route in the demo doesn't sync users
The route declares `payload` inside the `try` block and reads it after the block, so the call to `syncUser()` throws a `ReferenceError`. Until the code is fixed, create the user yourself: in the Permit dashboard, open **Directory** and add a user whose key is the Cognito `sub` value. The Cognito access token has no `name` or `email` claims, so read those from the ID token if you need them.
:::

### Permission checks \{#33-permit-authorization}

Authorization runs only on the backend. The `POST /say_hello` and `POST /wave_hello` routes verify the ID token, then call `permit.check()` with the user's `sub`, the action, and the `hello` resource. A route returns HTTP 200 only when the token is valid and Permit allows the action:

```js
app.post("/say_hello", async (req, res) => {
  try {
    const payload = await verifierIdToken.verify(
      req.headers.authorization?.split(" ")[1] // the JWT as string
    );
    // check the request body for the "message" property
    const permitted = await permit.check(
      payload.sub, // the user id
      "say", // the action
      "hello" // the resource
    );
    if (permitted) {
      res.status(200).send("Permitted! to say hello");
    } else {
      res.status(403).send("Not permitted to say hello");
    }
  } catch (error) {
    res.status(403).send("Token not valid!");
  }
});
//... handle the request
```

The `/wave_hello` route has the same code with the `wave` action.

## 4. Verify the demo \{#verify-the-demo}

1. Open `http://localhost:8181` and click **Login**. Sign up or sign in on the Cognito page.
2. In the Permit dashboard, open **Directory**. Find the user with the Cognito `sub` as its key, or add the user as described in the warning above. Assign the `viewer` role in the `default` tenant.
3. In the demo app, click the first **Say hello (if you have permission)** button. The app shows `Failed to say hello`, because `viewer` can't `say`.
4. Click the second button, which calls `/wave_hello`. The app shows `Waved hello`.
5. In Permit, assign the `admin` role to the user. Click the first button again. The app shows `Said hello`.
