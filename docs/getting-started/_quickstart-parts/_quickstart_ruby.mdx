### Install and initialize the Ruby SDK

Install the `permit-sdk` gem, load the SDK, and create a `Permit` client that connects to your PDP.

1. Install the Permit.io Ruby SDK:

```bash
gem install permit-sdk
```

2. Load the SDK in your code:

```ruby
require 'permit'
```

3. Create a `Permit` client with `Permit.new(token, pdp_url)`. Replace `TOKEN` with your environment API key. The second argument is the PDP URL, for example `http://localhost:7766`. The PDP URL is optional and defaults to `http://localhost:7766`.

```ruby
require 'permit'
permit = Permit.new("TOKEN", "http://localhost:7766") # the PDP url is optional
```

### Check permissions with the Ruby SDK

Call `permit.check()` with three arguments. `permit.check()` returns `true` when the policy allows the action, and `false` otherwise.

| Argument | Description |
|---|---|
| `user` | The user key as a string, or a hash with `key` and optional `first_name`, `last_name`, `email`, and `attributes`. The user key is typically the user ID from your authentication provider. |
| `action` | The action key as a string, for example `"create"`. |
| `resource` | The resource type key as a string, for example `"document"`, or a hash with `type`, `tenant`, and `attributes`. A string resource uses the `default` tenant. |

The following examples check whether the user `john@permit.io` can `create` a `document`. This example passes the user and the resource as strings:

```ruby
require 'permit'
permit = Permit.new("TOKEN", "http://localhost:7766") # the PDP url is optional

permitted = permit.check("john@permit.io", "create" , "document")
if permitted
  puts "john@permit.io is permitted to create a document"
else
  puts "john@permit.io is not permitted to create a document"
end
```

This example passes the user and the resource as hashes:

```ruby
require 'permit'
permit = Permit.new("TOKEN", "http://localhost:7766") # the PDP url is optional

user_hash = {"key": "john@permit.io", "first_name": "john", "last_name": "doe", "email": "john@permit.io"}
resource_hash = {"type": "document", "tenant": "default"}
permitted = permit.check(user_hash, "create" , resource_hash)
if permitted
  puts "john@permit.io is permitted to create a document"
else
  puts "john@permit.io is not permitted to create a document"
end
```

If `john@permit.io` exists in your environment and has a role that grants `create` on `document`, both examples print `john@permit.io is permitted to create a document`. Otherwise, the examples print `john@permit.io is not permitted to create a document`. To add users and assign roles, see [Sync users](/how-to/sync-users).

#### Check a permission in a specific tenant

In a multi-tenant application, pass the tenant key in the `tenant` field of the resource hash, as in the hash example above. To look up the keys of your tenants, call the [list tenants API](https://api.permit.io/v2/redoc#tag/Tenants/operation/list_tenants). In this example, replace `user`, `action`, `resource`, and `tenant` with a user key, action key, resource key, and tenant key from your environment:

```ruby
if permit.check("user", "action", { "type": "resource", "tenant": "tenant" })
  # Allow to close document
end
```

:::note Where checks run and where user data is stored
`permit.check()` sends each check to the PDP URL you configure. A container PDP evaluates checks on your machine, using policy and data that the PDP loads from Permit. Users, roles, and attributes that you create in the dashboard or sync through the Permit API are stored in the Permit control plane.
:::

### Check ABAC permissions with the Ruby SDK

An attribute-based access control (ABAC) policy grants permissions based on user and resource attributes, grouped into user sets and resource sets. See [ABAC policy components](/how-to/build-policies/abac/components). ABAC checks need a container PDP.

To check an ABAC policy, pass a resource hash with an `attributes` hash. In this example, `user` is a user key or user hash, and `close` and `resource` stand for an action key and a resource key from your environment:

```ruby
if permit.check(user, 'close', { "type": "resource", "attributes": {"hasApproval": "true"}, "tenant": "default" })
  # Allow to close document
end
```

For more check options, see [Check permissions with permit.check()](/how-to/enforce-permissions/check).

### Run a full Ruby example app

This single-file WEBrick app listens on port `4000` and runs a permission check on each request. The app uses the default PDP URL, `http://localhost:7766`.

1. Install the `permit-sdk` and `webrick` gems:

```bash
gem install permit-sdk webrick
```

2. Save the following code as `app.rb`. Replace `<YOUR_API_KEY>` with your environment API key, and `user@mail.com` with the key of a user in your environment.

```ruby
require 'webrick'
require 'permit'

permit = Permit.new("<YOUR_API_KEY>")

server = WEBrick::HTTPServer.new(Port: 4000)

server.mount_proc '/' do |_, res|
  res['Content-Type'] = 'application/json'

  permitted = permit.check("user@mail.com", "read", "document")
  if permitted
    res.status = 200
    res.body = { result: "user@mail.com is PERMITTED to read document!" }.to_json
    next
  end
  res.status = 403
  res.body = { result: "user@mail.com is NOT PERMITTED to read document" }.to_json
end

trap 'INT' do server.shutdown end

server.start
```

3. Run `ruby app.rb`.
4. Open `http://localhost:4000` in a browser.

If the user's role grants `read` on `document`, the page returns HTTP `200` with a JSON `result` of `user@mail.com is PERMITTED to read document!`. Otherwise, the page returns HTTP `403` with `user@mail.com is NOT PERMITTED to read document`.
