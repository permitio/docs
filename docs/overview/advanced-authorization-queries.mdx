Answer authorization questions that a single `permit.check()` can't: which of many resources a user can access, which users can act on a resource, and what a user can do across tenants. This walkthrough is for developers who already run permission checks and need to query permissions in bulk. Each section names the query, the SDK function that runs it, and a sample.

## Prerequisites

- A policy with users and role assignments ([Sync attributes, tenants, roles, and relationships](/overview/sync-applications-data))
- A Permit SDK connected to a policy decision point (PDP) ([Run the PDP](/overview/run-pdp))

## Choose a query

| Question | Query | Node.js | Python | Go | PDP endpoint |
|---|---|---|---|---|---|
| Can the user perform each of these actions on these resources? | [Bulk check](#bulk-check) | `permit.bulkCheck()` | `permit.bulk_check()` | `permit.BulkCheck()` | `POST /allowed/bulk` |
| Which of these objects can the user access? | [Filter objects](#filterobjects) | Not available | `permit.filter_objects()` | `permit.FilterObjects()` | |
| Which users can perform this action on this resource? | [Authorized users](#get-authorized-users) | Not available | `permit.authorized_users()` | Not available | `POST /authorized_users` |
| What can this user do, across tenants and resources? | [User permissions](#get-user-permissions) | `permit.getUserPermissions()` | `permit.get_user_permissions()` | `permit.GetUserPermissions()` | `POST /user-permissions` |

## The example scenario

Every query on this page uses the same blogging application. Alice and Bob are users, and each owns some blog posts.

| User | Blog posts | Permissions |
|---|---|---|
| Alice | Blog Post 1, Blog Post 2 | `edit`, `read` (Alice's own posts) |
| Bob | Blog Post 3 | `edit`, `read` (Bob's own post) |
| Alice | Blog Post 3 | `read` |
| Bob | Blog Post 1, Blog Post 2 | `read` |

The code samples show the shape of each call. Some samples use other users and resource names, such as `repo` or `document`. Replace them with your own user keys and resource types, for example `blog_post`.

## Bulk check

A bulk check sends several permission checks to the PDP in one request and returns one decision per check, in the same order as the checks. Use it when you need decisions for several resources or users at once, for example to show or hide actions in a list.

### Example: Alice checks which posts she can read \{#example-alice-checks-read-permissions}

Alice needs to know which blog posts she can read. Send one check per post, each with Alice's user key, the action `read`, and the post.

For Alice, the three decisions are `true`, `true`, and `true`: Alice can read Blog Post 1, Blog Post 2, and Blog Post 3. One request returns all three decisions, instead of one request per post.

## Filter objects \{#filterobjects}

Filtering objects removes the objects a user can't access from a list you already fetched. Fetch the records from your database, pass them to `FilterObjects()` (Go) or `filter_objects()` (Python), and get back the subset the policy allows, in the original order.

## Get user permissions

The user permissions query returns all of a user's permissions for every registered resource, in every tenant the user is assigned to. You can narrow the result to a list of tenants. The result maps each tenant or resource instance to the user's permissions and roles on it.
