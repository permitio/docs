Put Permit MCP Gateway in front of your Model Context Protocol (MCP) servers to add authentication, authorization, consent, and audit to every tool call your AI agents make. This page is for AI agent builders and platform teams choosing where to start.

Permit MCP Gateway is a proxy between MCP clients (Cursor, Claude Desktop, Claude Code, VS Code, and other AI tools) and the MCP servers they connect to. Each agent is one person using one MCP client. For each tool call, the gateway:

1. Identifies the agent and the person who signed in and approved it.
2. Checks the call in Permit.io against the trust level the person approved and the maximum an admin set.
3. Runs the checks an admin turned on: agent identity, the Guardian, and admin approval.
4. Logs the decision.

You don't add an SDK, rewrite agents, or change your MCP servers. You point the MCP client at the server's gateway URL, `https://<your-host>.agent.security/mcp/<server_key>`, instead of the MCP server URL. The diagram shows the path of one tool call.

## What the gateway gives developers and platform teams

- **A short setup:** create a host, import an MCP server, grant people access, and copy the server's gateway URL into the MCP client.
- **The MCP servers you use:** import any remote MCP server by its URL, including servers that require an OAuth sign-in. The gateway discovers the server's tools.
- **Client configuration to copy:** each MCP server's page shows its gateway URL and snippets for Cursor and VS Code, Claude Desktop, and Claude Code.
- **Pass-through runtime:** the gateway forwards allowed calls to the MCP server unchanged and returns an error to the agent for denied calls.

## What the gateway gives security, IAM, and governance teams

- **Per-person agents:** each tool call is bound to one person and one agent, so two people using the same MCP client are two agents.
- **Least privilege:** each tool has a trust level by risk (low for reads, medium for writes, high for deletes), and admins set the maximum trust level each person can approve on each server.
- **Consent with terms:** the person approves each agent on a consent screen, picks its trust level, can write the agent's task, and chooses when access ends.
- **Agent identity and the Guardian:** optional checks that stop an agent whose registered identity drifts and grade each call against the server's intent with an LLM judge.
- **Approvals:** admins can hold chosen tools, or a whole server, until an admin approves each call in the **Approvals** queue.
- **Visibility and audit:** the **Dashboard** shows live gateway activity, **Agents** shows each agent's sessions, **Consent Grants** lists every approval people gave, and each decision is logged with the person, the agent, the tool, and the server.
- **Deny by default:** nobody can use an imported MCP server until an admin grants access. A host that allows dynamic MCP connections also lets people connect to servers nobody imported.

Read the [Permit MCP Gateway overview](/permit-mcp-gateway/overview/) for the security and trust model and a comparison with API gateways and identity and access management (IAM) platforms.

## How the gateway uses Permit.io

Permit MCP Gateway runs on [Permit.io](https://www.permit.io). Permit is the control plane (where policies are defined) and the default data plane (where decisions are evaluated) for every gateway host.

- Each gateway **host** maps to one **Permit environment**. The policies, people, agents, and audit logs for that host live in the linked environment.
- Gateway policies can use Permit's policy models: role-based access control (RBAC), attribute-based access control (ABAC), and relationship-based access control (ReBAC), with policy updates applied without a restart. A change to a tool's trust level or a server's intent applies within about a minute.
- You work in two dashboards: **[app.agent.security](https://app.agent.security)** for hosts, MCP servers, people, agents, and approvals, and **[app.permit.io](https://app.permit.io)** for policies and audit logs. You sign in to both with your Permit.io account.

See [How Permit MCP Gateway works with Permit.io](/permit-mcp-gateway/permit-integration/) for the policy model.

## Prerequisites

- A [Permit.io](https://app.permit.io) account.
- Access to the [Permit MCP Gateway admin dashboard](https://app.agent.security), where you sign in with your Permit.io account to create hosts, import MCP servers, grant access, and review activity.
