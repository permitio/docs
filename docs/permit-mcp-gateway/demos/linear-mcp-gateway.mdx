In this tutorial, you put Permit MCP Gateway in front of the Linear MCP server and give two users different trust levels. A Developer with **High** trust can create Linear issues. A Project Manager with **Medium** trust can list issues, and the gateway denies issue creation. The tutorial is for admins who want to see trust levels enforced on a real MCP server before rolling out the gateway.

## Why put a gateway in front of Linear \{#problem-statement}

When several users or AI agents connect to Linear's MCP server, each one's agent can call every tool the user's Linear account allows. An intern's agent and a team lead's agent can both create issues, delete comments, and change projects. The Linear MCP server has no setting that limits which tools an agent can call.

Permit MCP Gateway sits between the MCP clients and the Linear MCP server and checks each tool call against the user's trust level.

| User | MCP client | Max trust level | Expected result |
| --- | --- | --- | --- |
| Developer | Claude Desktop | High | Can list and create issues |
| Project Manager | Claude Code | Medium | Can list issues; creating issues is denied |

## Before you begin \{#before-you-begin}

- A [Permit account](/quickstart/#1-create-a-permit-account).
- Access to the Permit MCP Gateway admin dashboard at [app.agent.security](https://app.agent.security). Click **Sign in with Permit.io**, then create or select an organization. See [Create or select an organization](/permit-mcp-gateway/host-setup#2-connect-your-permitio-organization).
- A Linear account you can sign in with.
- Claude Desktop for the Developer and Claude Code for the Project Manager. Any MCP client works; the tutorial uses these two.

## 1. Set up your host and the Linear MCP server \{#step-1--set-up-your-host-and-mcp}

For details on each field, see [Create a host](/permit-mcp-gateway/host-setup#3-create-a-host) and [Import MCP servers](/permit-mcp-gateway/host-setup#4-import-mcp-servers).

1. In the admin dashboard, open **Hosts** in the sidebar and click **Create Host**.

   ![Hosts page in a new organization with the Get Started checklist and the Create Host button](/img/agent-security/platform/hosts-get-started.png)

2. Fill in the fields:
   - **Subdomain:** a prefix, such as `linear-demo`. The dashboard adds a generated suffix, which you can't change.
   - **Project:** the Permit project that contains the environment you want to use.
   - **Environment:** **+ Create new environment** (the default) or one of the **Existing environments**. You can't change the environment after the host is created.
   - **Allow Dynamic MCP Connections:** on by default. When on, people can connect to MCP server URLs you haven't imported. After a host allows dynamic connections, you can't turn the setting off. This tutorial uses only the Linear server you import, so it works with either setting.

   ![Create Host form with a subdomain prefix, Default Project, a new environment, and Allow Dynamic MCP Connections on](/img/agent-security/platform/create-host-filled.png)

3. Click **Create Host**. In the **Confirm Host Creation** dialog, click **Create Host** again.

4. The host has no tools until you import an MCP server. Open **MCP Servers** and click **Create Server**. The **Import MCP Server** page opens.

   ![MCP Servers page with no servers and the Create Server button](/img/agent-security/platform/mcp-servers-empty.png)

5. Enter the Linear MCP URL, `https://mcp.linear.app/mcp`, and click **Connect**. Linear requires a sign-in, so the import page shows **Authorization Required**. Click **Sign in to MCP Server**. Linear asks you to approve the Agent Security Gateway. Click **Approve**, and sign in to Linear if Linear asks. The browser returns to the import page.

   ![Linear authorization page saying Agent Security Gateway is requesting access, with Cancel and Approve buttons](/img/mcpermit/linear-demo/linear-mcp-url.png)

6. On the **Review & Configure** step, fill in the server details:
   - **Server Key:** a unique identifier of lowercase letters, underscores, and numbers, such as `linear_mcp_demo`.
   - **Display Name:** the name people see during consent, such as `Linear MCP`.
   - **Description (optional)** and **Workflow intent (optional):** you can leave both empty for this tutorial. When the Guardian is on for the host, it uses the workflow intent to check that each tool call fits the server's purpose.

7. **Tools to Import** lists every Linear MCP tool with a checkbox, a trust select (**Low**, **Medium**, or **High**), and an **HITL** switch that requires an admin's approval before each call. This tutorial uses two tools, `list_issues` and `save_issue`. Set `save_issue` to **High** and `list_issues` to **Medium**. A level you change shows **(custom)**. Leave the **HITL** switches off.

8. Click **Import Server & N Tools**, where N is the number of selected tools. The **Server Created Successfully** dialog offers to give people access. Nobody has signed in to the host yet, so click **Skip for Now**.

For a screenshot of the **Review & Configure** step, see [Import MCP servers](/permit-mcp-gateway/host-setup#4-import-mcp-servers). You can change tool trust levels later in the **Tools** card on the server's page.

The host now proxies the Linear MCP server's tools.

## 2. Connect users and grant access \{#step-2--add-users}

Each user connects an MCP client to the gateway instead of to Linear.

Each imported MCP server has its own gateway URL. Open **MCP Servers** and select **Linear MCP**. The **MCP URL** card shows the server's URL, `https://<your-subdomain>.agent.security/mcp/<server_key>`, with a snippet for **Cursor / VS Code**, **Claude Desktop**, and **Claude Code**. With that URL, the consent flow connects to Linear without showing a server list.

This tutorial gives both users the host-level URL instead: `https://<your-subdomain>.agent.security/mcp`, the same address without the server key. With the host-level URL, the consent screen lists the MCP servers each user has access to, so you can watch the list change when you grant access. Your host's address is on its card on the **Hosts** page and in the host chip in the top bar. For both kinds of URL and every client snippet, see [Share the MCP URL with your team](/permit-mcp-gateway/host-setup#7-share-the-host-url-with-your-team).

### Connect the Developer with Claude Desktop \{#developer-signs-up-with-claude-desktop}

1. In Claude Desktop, the Developer adds a custom connector with the host-level gateway URL and connects.

   ![Claude Desktop Add custom connector dialog with the name linear-mcp-demo and the gateway URL](/img/mcpermit/linear-demo/consent-signin.png)

2. Claude Desktop opens the host's **Sign In** page in the browser. The Developer signs in, or clicks **Create Account** to register. On the hosted gateway, a new account verifies its email address first: a **Check your email** page asks the Developer to open the link in the email.

   ![Sign In page on the host with Email and Password fields, a Sign In button, and a Create Account button](/img/agent-security/consent/login.png)

3. After signing in, the Developer sees the **Connect MCP Server** screen with no servers to pick. No admin has granted access yet, so the screen says "No MCP servers available. Contact your administrator to grant you access to MCP servers."

   ![Connect MCP Server screen for Claude saying No MCP servers available, with a Refresh list button](/img/mcpermit/linear-demo/no-mcps.png)

4. As the admin, open **Humans** in the admin dashboard. The Developer appears in the **Human Users** table. Open the Developer and, in the **MCP Server Access** card, click **Grant Access**. In the **Grant MCP Server Access** dialog, select **Linear MCP** as the **MCP Server**, set **Max trust** to **High** (the default is **Low**), and click **Grant Access**. For a screenshot of the dialog, see [Grant access to an MCP server](/permit-mcp-gateway/managing-humans-and-agents#granting-access-to-an-mcp-server).

5. The Developer clicks **Refresh list** on the consent screen. **Linear MCP** appears with a **High Trust** badge, the Developer's max trust level. The Developer selects **Linear MCP** and clicks **Select**.

   ![Connect MCP Server screen listing Linear MCP with a High Trust badge, some of its tools, and a Refresh list button](/img/mcpermit/linear-demo/mcp-available.png)

6. Linear requires a sign-in, so the consent screen shows **Authorization Required**: "This server requires you to sign in first." The Developer clicks **Sign in to Continue** and approves the Agent Security Gateway on Linear's authorization page.

   ![Linear authorization page asking to approve Agent Security Gateway, with Cancel and Approve buttons](/img/mcpermit/linear-demo/connected.png)

7. The review screen opens with Linear MCP as the **Target Server**. The Developer sets the terms:
   - **Trust Level:** the slider starts at **Medium** and stops at **Max: High**. Drag it to **High**. The agent's effective trust level is the lower of the level picked here and the Developer's max trust, so an agent approved at Medium can't call `save_issue`.
   - **Task and expiry:** leave the defaults. The agent reports its own task when it connects, and access never expires.
   - **Ask me before this agent changes or deletes anything:** leave the switch off. When it is on, changes wait for the Developer's approval by email.

   The **Available Tools** list shows each tool as **Allowed** or **Denied** at the chosen level. The Developer clicks **Accept**, and Claude Desktop finishes connecting.

For every field on the review screen, with a screenshot, see [Sign in and approve the agent](/permit-mcp-gateway/quickstart#4-authenticate-and-use) and [Consent Service](/permit-mcp-gateway/consent-service).

### Connect the Project Manager with Claude Code \{#project-manager-signs-up-with-claude-code}

The Project Manager follows the same steps with Claude Code. To add the gateway, the Project Manager runs this command, with `<your-subdomain>` replaced by your host's subdomain:

```bash
claude mcp add linear-demo --transport http "https://<your-subdomain>.agent.security/mcp"
```

When you grant access on the **Humans** page, set **Max trust** to **Medium** instead of High. After the grant, the Project Manager's consent screen lists Linear MCP with a **Medium Trust** badge:

![Connect MCP Server screen for Claude Code listing Linear MCP with a Medium Trust badge](/img/mcpermit/linear-demo/pm-medium-trust.png)

On the review screen, the **Trust Level** slider stops at **Max: Medium**. The Project Manager leaves it at **Medium** and clicks **Accept**.

## 3. Test tool calls for each user \{#step-3--test-actions-by-user}

### Project Manager tries to create an issue \{#pm-claude-code-tries-to-create-issue}

Ask Claude Code to create a Linear issue. The Project Manager's Medium trust is below the High trust `save_issue` requires, so the gateway denies the call with MCP error `-32004` and a "Permission denied" message that names `save_issue`.

![Claude Code showing MCP error -32004, Permission denied for tool save_issue](/img/mcpermit/linear-demo/pm-create-denied.png)

To see the denial in the admin dashboard, open **Agents**, expand the Project Manager, open the agent, and select the **Audit Logs** tab.

### Developer creates an issue \{#developer-claude-desktop-tries-to-create-issue}

Ask Claude Desktop to create a Linear issue. The Developer has High trust, so the issue is created.

![Claude Desktop creating a Linear issue](/img/mcpermit/linear-demo/dev-create-success.png)

### Both users list issues \{#both-users-list-issues}

Ask each client to list Linear issues. Both users meet the Medium trust `list_issues` requires, so both calls succeed.

![Claude Code listing Linear issues for the Project Manager](/img/mcpermit/linear-demo/pm-list-issues.png)

![Claude Desktop listing Linear issues for the Developer](/img/mcpermit/linear-demo/dev-list-issues.png)

## Results \{#summary}

| User | Trust level | `list_issues` (Medium) | `save_issue` (High) |
|------|-------------|----------------------|---------------------|
| Developer | High | Allowed | Allowed |
| Project Manager | Medium | Allowed | Denied |

Permit MCP Gateway enforced a different set of Linear tools for each user, with no change to the Linear MCP server.
