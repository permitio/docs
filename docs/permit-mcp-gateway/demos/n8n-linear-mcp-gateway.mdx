In this tutorial, you connect an n8n workflow to the Linear MCP server through Permit MCP Gateway. The workflow creates a Linear issue for each new customer in Attio. You then lower the workflow's trust level in the gateway and watch the gateway block the same call. The tutorial is for admins and workflow builders who run automated agents against MCP servers.

## Why route n8n through the gateway \{#problem-statement}

Workflow builders such as n8n can call external MCP servers with no person reviewing each call. Permit MCP Gateway checks every tool call the workflow makes against the trust level granted to the workflow, so you control which tools the workflow can use and can change that access at any time.

## Before you begin \{#before-you-begin}

- A [Permit account](/quickstart/#1-create-a-permit-account).
- A Permit MCP Gateway host with the Linear MCP server imported, and access granted to your user. Follow steps 1 and 2 of the [Linear MCP Gateway demo](/permit-mcp-gateway/demos/linear-mcp-gateway), or see [Set up hosts for your organization](/permit-mcp-gateway/host-setup).
- An n8n instance where you can add the **MCP Client** node.
- An Attio workspace with an object that tracks customers, if you want to run the full workflow. Only the MCP Client part of the workflow involves the gateway.

## The n8n workflow

The example workflow uses **Attio** (CRM) and **Linear** (project tracking). For every new sale recorded in an Attio object, the workflow creates a Linear issue.

The workflow has three nodes:

| Node | What it does |
| --- | --- |
| **API Webhook Listener (Attio)** | Listens for new items added to the Attio object. |
| **HTTP Fetcher** | Retrieves the new item's data from Attio. |
| **MCP Client** | Calls Permit MCP Gateway to create a Linear issue with the item's data. |

![n8n workflow with webhook, HTTP fetcher, and MCP Client nodes](/img/mcpermit/n8n-linear-demo/workflow-overview.png)

The webhook and fetcher nodes are standard n8n nodes and don't involve the gateway. The steps below cover the **MCP Client** node.

## 1. Configure the MCP Client node in n8n \{#step-1--configure-the-mcp-client-in-n8n}

1. In your n8n workflow, add **MCP Client** from the node selector on the right.

   ![MCP Client in the n8n node selector](/img/mcpermit/n8n-linear-demo/mcp-client-tool-selector.png)

2. Enter the gateway MCP URL of the host where you imported the Linear MCP server. For **Authentication**, select **MCP OAuth2**, then **Create New Credential**.

   ![MCP Client node with the gateway URL and MCP OAuth2 authentication](/img/mcpermit/n8n-linear-demo/mcp-client-config.png)

3. In the **Create New Credential** dialog, enter the gateway MCP URL again as the MCP endpoint URL and click **Connect to MCP**.

   ![Create New Credential dialog with the MCP endpoint URL](/img/mcpermit/n8n-linear-demo/create-credential.png)

4. The Consent Service opens. Select the **Linear MCP** server for this workflow.

   ![Consent Service with the Linear MCP server selected](/img/mcpermit/n8n-linear-demo/consent-service-select.png)

5. Sign in and authorize access to Linear. The Consent Service then shows Linear's tools with their trust levels, and you set the trust granted to the n8n workflow. The trust you grant decides which Linear tools n8n can call. For how the consent screen maps trust levels to tools, see [Consent Service](/permit-mcp-gateway/consent-service).

   ![Consent Service listing Linear tools with trust levels](/img/mcpermit/n8n-linear-demo/tool-import.png)

## 2. Configure the Linear action \{#step-2--configure-the-linear-action}

1. In the MCP Client node, n8n lists the Linear tools available through the gateway. Select **save_issue**.

   ![MCP Client node with save_issue selected](/img/mcpermit/n8n-linear-demo/select-save-issue.png)

2. Set the Linear **team** for the issue, then map the data from Attio. This example uses the customer name and sale amount for the issue title and description.

   ![save_issue fields mapped to Attio customer data](/img/mcpermit/n8n-linear-demo/issue-config.png)

## 3. Test the workflow \{#step-3--test-the-workflow}

Add an item to the Attio object. With a trust level that allows `save_issue` (High in the Linear demo), the workflow runs and creates a Linear issue.

![n8n execution with all nodes completed](/img/mcpermit/n8n-linear-demo/workflow-complete.png)

![Linear issue created from the Attio item's data](/img/mcpermit/n8n-linear-demo/linear-issue-created.png)

![Attio item that triggered the workflow](/img/mcpermit/n8n-linear-demo/attio-item.png)

## 4. Change the workflow's trust level \{#step-4--adjust-trust-levels-in-real-time}

To change what the n8n workflow can do on the Linear MCP server, change its trust level in the Permit MCP Gateway admin dashboard. The gateway applies the new trust level to the workflow's next tool call. See [Modifying agent trust levels](/permit-mcp-gateway/managing-humans-and-agents#modifying-agent-trust-levels).

![Admin dashboard showing the trust level controls for the n8n agent](/img/mcpermit/n8n-linear-demo/trust-level-dashboard.png)

![Trust level set to Low for the n8n agent](/img/mcpermit/n8n-linear-demo/trust-level-low.png)

Set the trust level to **Low** and add another Attio item. The gateway denies `save_issue`, and the MCP Client node fails.

![n8n execution log showing the MCP Client node blocked by the gateway](/img/mcpermit/n8n-linear-demo/execution-blocked.png)

## Results \{#summary}

| Trust level | `save_issue` result |
|-------------|-------------------|
| High | Allowed: the issue is created |
| Low | Blocked: Permit MCP Gateway denies the call |

You changed what the n8n workflow can do on the Linear MCP server from the gateway, with no change to the Linear MCP server or the n8n workflow.
