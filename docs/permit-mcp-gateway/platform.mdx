This reference is for admins of Permit MCP Gateway. It describes each page of the admin dashboard at [app.agent.security](https://app.agent.security) in sidebar order, and links to the guide that owns each task.

| Task | Guide |
| --- | --- |
| Create a host and import MCP servers | [Set up hosts for your organization](/permit-mcp-gateway/host-setup) |
| Grant, lower, and revoke access for humans and agents | [Manage humans and agents](/permit-mcp-gateway/managing-humans-and-agents) |
| Configure sign-in methods and SSO | [Authentication methods reference](/permit-mcp-gateway/authentication-methods) |
| Turn on agent identity and the Guardian | [Check agent identity and intent](/permit-mcp-gateway/advanced-features) |
| Review approval requests | [Human-in-the-loop approvals](/permit-mcp-gateway/human-in-the-loop) |
| Investigate allowed and denied calls | [Audit logs](/permit-mcp-gateway/audit-logs) |

## Prerequisites

- A [Permit.io](https://app.permit.io) account. You sign in to the admin dashboard with it.
- Membership in a Permit organization, or the right to create one. Most changes in the dashboard need the **admin** access level in that organization. A control your access level can't use is disabled, and its tooltip names the role it needs, for example "Requires admin role in this organization".

## Sign in

Go to [app.agent.security](https://app.agent.security) and click **Sign in with Permit.io**. The admin dashboard has no separate sign-up and no API key step. The organizations you can open are the ones your Permit account belongs to.

## Navigation

The admin dashboard has a sidebar on the left and a host chip in the top bar.

![Hosts page in a new organization, showing the sidebar, the organization switcher, and the host chip with no host selected](/img/agent-security/platform/hosts-get-started.png)

### Sidebar

| Page | What it does |
| --- | --- |
| **Dashboard** | Shows gateway activity for the current host: governed calls, denials, pending approvals, and a live feed. |
| **Hosts** | Lists the organization's hosts and creates new ones. |
| **MCP Servers** | Imports upstream MCP servers and manages their tools, intent, and access. |
| **Approvals** | Lists pending [human-in-the-loop](/permit-mcp-gateway/human-in-the-loop) approval requests and their history, and configures notifications. |
| **Agents** | Lists every agent (one person using one MCP client), its sessions, and the intent it declared in each session. |
| **Humans** | Lists the people who can sign in on the host, invites people by email, and manages their MCP server access. |
| **Consent Grants** | Lists every approval a person gave an agent, with its level, task, end date, and history. |
| **Agent Fingerprints**, **Shadow Agents** | Locked previews, marked **Pro** in the sidebar. |
| **Settings** | Configures the current host: environment, Dynamic MCP Connections, Agent Identity, approval and grant timing, upstream JWT, authentication methods, and host deletion. |
| **Get Help** | Opens the [Permit community Slack](https://io.permit.io/slack). |

### Organization switcher

The organization switcher sits at the top of the sidebar and shows the current organization, for example **Organization: Acme Corp**. Open it to search your organizations with **Search organizations...** and switch between them. Each organization has its own hosts, MCP servers, users, and policies. The **+** button (**Add organization**) opens the [Organizations page](#organizations-page).

![Organization switcher open in the sidebar, with the search box and the plus button](/img/agent-security/platform/org-switcher.png)

### Host chip

The host chip in the top bar shows the current host, for example **Host acme-zesty-magenta-11 acme-zesty-magenta-11.agent.security**. The Dashboard, MCP Servers, Approvals, Agents, Humans, Consent Grants, and Settings pages show data for the current host. The chip's menu has three items:

- **Switch host**: lists the organization's hosts. Select one to make it the current host.
- **All hosts**: opens the **Hosts** page.
- **Add host**: opens the **Create Host** form.

When no host is selected, the chip reads **No host selected Choose one**, and a **Select Host** dialog asks you to "Choose a host to manage, or create a new one."

![Host chip menu open, with Switch host, All hosts, and Add host](/img/agent-security/platform/host-menu.png)

### Multi-organization support

One Permit account can belong to several Permit organizations, and the admin dashboard shows each of them. Use the organization switcher to move between them. To create a new organization, see [Organizations page](#organizations-page).

## Organizations page

The **Organizations** page lists the Permit organizations your account belongs to. The current one is marked **Active**. Click **Select** on another organization to switch to it.

To create an organization:

1. Click **Create Another Organization**. If your account has no organizations yet, the page shows the form right away.
2. Enter an **Organization name**, such as `Acme Corp`.
3. Enter an **Organization key**. Use lowercase letters, numbers, and dashes only.
4. Click **Create**. If your account had no organizations, the button is **Create Organization**.

The admin dashboard creates the organization in Permit with your Permit account.

## Hosts \{#hosts-management}

A **host** is an instance of Permit MCP Gateway with its own subdomain, Permit environment, users, MCP servers, and settings. Each host uses one Permit environment, and each environment can be used by only one host.

The **Hosts** page has two parts:

- **Get Started**: a three-step checklist (**Create Host**, **Add MCP Server**, **Add Users**). It also appears on the Dashboard until every step is complete.
- **Hosts Selector**: one card per host, with its subdomain, URL, project, and environment. The current host has a **Current** badge. Click a card to make that host the current host and open its **Settings**.

![Hosts page with the Get Started checklist at 1 of 3 steps and the acme-zesty-magenta-11 host card marked Current](/img/agent-security/platform/hosts.png)

### Creating a host

Click **Create Host** on the Hosts page, or **Add host** in the host chip menu. For the fields, the confirmation dialog, and the full procedure, see [Create a host](/permit-mcp-gateway/host-setup#3-create-a-host).

Each host's URL has this format:

```
https://<prefix>-<adjective>-<color>-<number>.agent.security
```

You choose the prefix: lowercase letters, numbers, and hyphens, up to 33 characters, with no hyphen at the start or the end. The dashboard adds a generated suffix (an adjective, a color, and a number) so that the subdomain is unique. You can't change the suffix. A host with the prefix `acme` gets a subdomain such as `acme-zesty-magenta-11.agent.security`.

MCP clients connect to one MCP server at `https://<subdomain>.agent.security/mcp/<server_key>`, or to the host-level URL `https://<subdomain>.agent.security/mcp`, which lets the person pick a server during consent. Each MCP server's page shows its URL and client snippets.

### Deleting a host

1. Make the host current, and open **Settings** in the sidebar.
2. In **Danger Zone**, click **Delete Host**.
3. Confirm with **Delete Host**.

Deleting a host removes the host, its consent grants, and the sign-in data on its subdomain, such as registered MCP clients and authentication settings. The Permit environment linked to the host isn't deleted.

:::warning
Deleting a host can't be undone. MCP clients configured with the host's URLs can no longer connect, and every agent on the host stops working.
:::

## Dashboard

The **Dashboard** shows what is happening on the current host's gateway. Pick a time range of **1h**, **6h**, **24h**, or **7d**.

| Section | Contents |
| --- | --- |
| **Gateway activity** cards | **Governed calls**, **Allowed** (with the number denied and flagged by the Guardian), **Exfiltration blocked (DLP)**, and **Approvals pending (HITL)** with a link to the approval queue. |
| **Governed call volume by outcome** | A chart of calls by outcome: Allowed, Denied, and Guardian flagged. |
| **Top denied intents** | Denied calls, grouped by what the Guardian graded each call against. |
| **Top agents by denials** | The agents with the most denied calls. |
| **Live activity** | A live feed of calls, with **All** and **Blocked** filters and a pause button. |

The Dashboard doesn't show MCP URLs or client snippets. Each MCP server's page has them.

## MCP Servers \{#mcp-server-management}

The **MCP Servers** page lists the current host's MCP servers in two tabs:

- **Static**: servers an admin imported. Each card shows the server's name, key, description, and an **Intent set** badge when the server has a workflow intent.
- **Dynamic**: servers people connected by URL during consent, when the host allows dynamic MCP connections. See [Dynamic servers](#dynamic-servers).

Admins import a server with **Create Server**.

![MCP Servers page with the Cloudflare Docs and DeepWiki cards, both marked Intent set](/img/agent-security/platform/mcp-servers.png)

### Import wizard

The **Import MCP Server** wizard connects to an upstream MCP server, discovers its tools, and creates the matching resources and permissions in Permit. It has three steps: **Connect**, **Review & Configure**, and **Import**. For the procedure, including upstream servers that need a sign-in, see [Import MCP servers](/permit-mcp-gateway/host-setup#4-import-mcp-servers).

### Tool auto-discovery and trust level classification

During import, the gateway discovers every tool the upstream MCP server exposes and classifies each tool into a trust level by keywords in the tool name. The match is case-insensitive and finds the keyword anywhere in the name. High keywords are checked first.

| Trust level | Classification | Naming patterns |
| ----------- | -------------- | --------------- |
| **Low** | Read-only operations (default) | Tools not matching medium or high patterns |
| **Medium** | Write operations | `create`, `write`, `update`, `set`, `modify`, `edit`, `put`, `post`, `insert`, `add`, `send`, `execute`, `run`, `invoke`, `submit`, `push`, `publish`, `deploy`, `apply`, `patch` |
| **High** | Destructive operations | `delete`, `remove`, `destroy`, `drop`, `purge`, `erase`, `truncate`, `terminate`, `kill`, `revoke` |

Trust levels are hierarchical. **High** includes all Medium and Low permissions, and **Medium** includes all Low permissions.

### Overriding trust levels

You can change a tool's trust level during import or after import. After import:

1. Open **MCP Servers** and select the server.
2. In the **Tools** card, find the tool.
3. Select a level in the tool's trust select.

Changing a tool's trust level needs the admin or write access level. Change a tool's level when its name doesn't reflect its risk. For example, DeepWiki's `ask_wiki_question` has no Medium or High keyword, so it is classified as Low, but you may want to require Medium for it.

### Server detail view

Each MCP server's page has three tabs: **Overview**, **Audit Logs**, and **Dry Run**. The **Overview** tab has these cards, in order:

| Card | Contents |
| --- | --- |
| **Intent** | The workflow intent the Guardian grades calls to this server against, with **Edit intent**. It also says whether the Guardian is on for the host. |
| **MCP URL** | The server's gateway URL, `https://<subdomain>.agent.security/mcp/<server_key>`, and client snippets in **Cursor / VS Code**, **Claude Desktop**, and **Claude Code** tabs. |
| **Authorized Humans** | The people who can connect to this server, each with a max trust level. **Grant Access** adds a person or invites one by email. |
| **Server Approval Policy** | **Require approval for all tools**, and a **Trust level threshold**: tools at that trust level or higher require approval. See [Human-in-the-loop approvals](/permit-mcp-gateway/human-in-the-loop). |
| **Trusted Agent Bypass** | Agents that skip the human approval step on this server. Permit still checks every call. |
| **Tools** | Every tool, with **Dry Run**, a **HITL** switch that requires approval for the tool, a trust select, and a delete button. **Re-sync Tools** reads the tool list from the upstream server again. **Add Tool** adds a tool by hand. |
| **Configuration** | The server's **Name**, **Description**, and **Upstream URL**, with **Save Changes**. |
| **Danger Zone** | **Delete Server**. |

The **Audit Logs** tab lists the calls to this server. See [Audit logs](/permit-mcp-gateway/audit-logs). For how to edit each card, see [Manage an MCP server after import](/permit-mcp-gateway/host-setup#manage-an-mcp-server-after-import).

![DeepWiki server page with the Overview, Audit Logs, and Dry Run tabs, the Intent card, and the MCP URL card](/img/agent-security/platform/server-overview.png)

### Dry Run

The **Dry Run** tab tries a tool call the way an agent would make it, without making it. The Guardian grades the call, and the result shows whether the call would run, wait for an approval, or be denied, and why. Nothing reaches the upstream server and no audit row is written.

- Only admins see the tab, and only on static servers.
- A host gets 10 dry runs a minute, shared by its admins. Each run is a real call to the Guardian's AI model.

For the steps, see [Test a call with Dry Run](/permit-mcp-gateway/host-setup#test-a-call-with-dry-run).

![Dry Run result for ask_wiki_question, with the gates, the judge's alignment and confidence scores, and the intent it was graded against](/img/agent-security/platform/server-dry-run.png)

### Dynamic servers

A dynamic server appears on the **Dynamic** tab after a person connects to an MCP server by URL during consent. Its page shows the person and the upstream URL. Compared with a static server's page:

- There is no **Intent** card, so the Guardian grades its calls against the person's task when the person set one, and otherwise against the agent's own registered words.
- **Authorized Humans** lets you change the person's max trust, but not grant or revoke access.
- **Tools** lets you change trust levels, but has no **Re-sync Tools**.
- There is no **Server Approval Policy**, **Trusted Agent Bypass**, **Configuration**, **Danger Zone**, or **Dry Run** tab.

The MCP URL of a dynamic server has the form `https://<subdomain>.agent.security/mcp?upstream_mcp=<url>`.

## Approvals

The **Approvals** page lists tool calls that wait for an admin's decision. It has three tabs:

- **Pending**: one card per waiting call, with the agent, tool, server, and person, a countdown, **Approve** and **Reject**, and why the call is waiting.
- **History**: past decisions.
- **Notifications**: email recipients and a Slack incoming webhook URL.

For the full workflow, see [Human-in-the-loop approvals](/permit-mcp-gateway/human-in-the-loop).

![Approvals page with one pending request from Acme Research Agent](/img/agent-security/platform/approvals-pending.png)

## Agents \{#agent-management}

The **Agents** page lists every agent on the current host. Each agent is one person using one MCP client. An agent appears after the person completes the [consent flow](/permit-mcp-gateway/consent-service).

- **List** and **Map** views. The list is a tree of people, their agents, and each agent's sessions.
- Filters: **Search** (person, client ID, session, or intent), **Person**, **Agent**, **Server**, **Session status** (**All**, **Active**, **Blocked**, **Ended**), and **Intent missing only**.
- Columns: **Name**, **Current intent**, **Servers**, **Trust**, **Status**, and **Last seen**.
- Each session row has **Block Session**. Each agent row has a menu with **View details**, **Rename**, and **Revoke**.

An agent's page shows its name, the person and server it acts for, and its trust level. Its **Overview** tab has the **Sessions**, **Access**, and **Registrations** cards, and its **Audit Logs** tab lists its calls. For what each card does and how to block, lower, rename, and revoke, see [Manage agents](/permit-mcp-gateway/managing-humans-and-agents#managing-agents).

![Agents list with Check TheDog's email, the Acme Research Agent, and its sessions, each with Block Session](/img/agent-security/platform/agents.png)

## Humans \{#human-management}

The **Human Users** page lists the people who signed up on the current host, with their **Name**, **Email**, **Identity ID**, and **Type**. People you invited who haven't signed up yet appear under **Pending Invites**. **Invite by Email** pre-authorizes a person before they sign up.

A person's page has **Overview** and **Audit Logs** tabs. The **Overview** tab has these cards:

- **User Information**: user ID, first name, last name, and email.
- **MCP Server Access**: the servers the person can connect to during consent, each with a max trust level. **Grant Access** adds a server.
- **Connected Agents**: the person's agents, with server, trust level, and sessions.
- **Approval verification**: how the person proves it's them before deciding their agents' approvals.
- **Danger Zone**: **Delete User**.

A person has no access to any MCP server until an admin grants it. For procedures, and how revoking a person's access affects their agents, see [Manage humans](/permit-mcp-gateway/managing-humans-and-agents#managing-humans).

![Check TheDog's page with User Information and MCP Server Access, DeepWiki at High](/img/agent-security/platform/human-detail.png)

## Consent Grants

The **Consent Grants** page lists every approval a person gave an MCP agent on the current host, one row per person, agent, and server. Columns: **Agent**, **Server**, **Level**, **Task**, **Ends**, **Status**, and **Sessions**. The status is **Active**, **Expiring soon**, **Paused**, **Expired**, or **Revoked**.

**Recent changes** shows the last five events on the host. **View all history** opens the full history: every approval, change, pause, expiry, and revoke, newest first. See [Review consent grants](/permit-mcp-gateway/managing-humans-and-agents#review-consent-grants).

![Consent Grants with one approval of Acme Research Agent on deepwiki at Low, ending in 7 days, and Recent changes](/img/agent-security/platform/consent-grants.png)

## Agent Fingerprints and Shadow Agents

**Agent Fingerprints** and **Shadow Agents** are locked previews. Each page shows sample data behind a lock with a **Contact Permit.io** button.

## Settings

**Settings** in the sidebar configures the current host. The page starts with the host's subdomain, a **Current Environment** chip, and the host URL, followed by these sections in order:

| Section | What it controls |
| --- | --- |
| **Environment** | The host's Permit project and environment. Read-only: the environment can't be changed after the host is created. |
| **Policy Decision Point (PDP)** | The PDP URL the host uses. Shown only on [on-prem installations](/permit-mcp-gateway/on-prem-installation). |
| **Dynamic MCP Connections** | Whether people can connect to any MCP server URL. See [Dynamic MCP Connections](#dynamic-mcps). |
| **Agent Identity** | Three layers that check every agent call: **Semantic identity**, **Agent intent**, and **Guardian**. See [Check agent identity and intent](/permit-mcp-gateway/advanced-features). |
| **Sign-in check for people's approvals** | How recent a person's sign-in must be before they decide their agent's approval: 5 min, 15 min (default), 1 hour, 8 hours, or Custom. |
| **Expiring consent grants** | How long before a grant ends it shows **Expiring soon**: 1 hour, 1 day, 2 days (default), 7 days, 30 days, or Custom. |
| **Upstream Authentication (JWT)** | The gateway signs a short-lived JWT in an `X-Gateway-Auth` header on every upstream request. The section shows the JWKS URL, `https://<subdomain>.agent.security/.well-known/gateway-jwks.json`, and a verification example. |
| **Authentication Methods** | How people sign in on the host. See [Authentication methods](#authentication-methods). |
| **Danger Zone** | **Delete Host**. See [Deleting a host](#deleting-a-host). |

### Dynamic MCP Connections \{#dynamic-mcps}

When **Allow Dynamic MCP Connections** is off, people can connect only to MCP servers an admin imported. When it's on, the consent screen also lets people enter any MCP server URL. A server added this way appears on the **Dynamic** tab of the MCP Servers page. The gateway still authorizes every tool call with Permit and records it in the audit log.

The switch is on by default when you create a host. To turn it on later, switch **Allow Dynamic MCP Connections** on and click **Enable** in the **Enable Dynamic MCP Connections?** confirmation.

:::warning
The setting is one-way. Once **Allow Dynamic MCP Connections** is on, the switch shows **Strict → open only** and can't be turned off, so people on the host can keep connecting agents to MCP servers you haven't imported or reviewed. To keep a host limited to imported servers, turn the switch off when you create the host.
:::

### Authentication methods

Each host has its own authentication methods. **Email / Password** is on by default. For setup instructions, identity provider examples, and callback URLs, see the [Authentication methods reference](/permit-mcp-gateway/authentication-methods).

| Method | Description in the dashboard |
| --- | --- |
| **Email / Password** | Traditional email and password sign-in |
| **Email OTP** | Passwordless sign-in via email code |
| **Passkeys** | WebAuthn/FIDO2 biometric or hardware key |
| **Google**, **GitHub**, **Microsoft** | Sign in with that provider |
| **Enterprise OIDC** | OpenID Connect federation |
| **Enterprise SAML** | SAML 2.0 federation |

Only one enterprise single sign-on (SSO) method, OIDC or SAML, can be active at a time. Click **Add method** to add a method, and **Save Configuration** to save.

![Authentication Methods section with Email / Password, Global Email Domain Restriction, and Add method](/img/agent-security/platform/settings-auth-methods.png)

### Domain restrictions

Restrict sign-in to allowed email domains, such as `acme.com`:

- **Global Email Domain Restriction**: applies to every method on the host.
- **Email Domain Restriction**: applies to one method.

For how global and per-method restrictions combine, see [Domain restrictions](/permit-mcp-gateway/authentication-methods#domain-restrictions).

### SAML / OIDC SSO setup

For **Enterprise SAML**, the method shows the service provider (SP) details to enter in your identity provider: **ACS (Assertion Consumer Service) URL**, **SP Entity ID / Audience URI**, and **SP Metadata URL**. For **Enterprise OIDC**, it shows the **Redirect URI (Callback URL)** and **Scopes**. The identity provider walkthroughs are in the [Authentication methods reference](/permit-mcp-gateway/authentication-methods).

#### Force SSO for domains \{#force-redirect-domains}

For an enterprise SSO method, **Force SSO for Domains** sends a person to the SSO provider as soon as they type an email that matches one of the listed domains on the sign-in screen.
