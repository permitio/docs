Call the Permit.io REST API directly from curl, Postman, or any HTTP client. This page is for developers who automate Permit, for example to sync users or tenants from a script. Every action in the Permit dashboard calls the same API, so anything you do in the dashboard you can also do through the API.

## Prerequisites

- A Permit.io account with a project and an environment. See [Projects and environments](/manage-your-account/projects-and-env).
- The keys or IDs of the project and environment you call. See [Get the project and environment](/api/examples/get-project-and-env).

## Get your API key \{#get-your-api-key}

Every Permit API request needs an API key in the `Authorization` header.

1. In the Permit dashboard, go to [Settings > API Keys](https://app.permit.io/settings/api-keys).

   ![API Keys tab in the Permit dashboard Settings screen, listing existing API keys](/img/api_keys/api_keys.png)

2. Reveal and copy an existing API key, or click **Create Key** to create one.

   ![Create Key dialog on the API Keys tab of the Permit dashboard](/img/api_keys/create_api_key.png)

Permit has three API key levels:

| API key level | Scope |
| --- | --- |
| Organization API key | The whole workspace: every project and environment. Use it for calls that are not environment-specific, such as creating projects. |
| Project API key | One project and all of its environments. |
| Environment API key | One environment. Only an environment API key works with the policy decision point (PDP) container. |

For when to use each level, see [API keys in workspace settings](/manage-your-account/workspace-settings#api-keys). To copy the environment API key from the Projects screen instead, see [Get your API key](/overview/get-api-key).

## Call the API with curl \{#using-curl}

Pass the API key as a bearer token in the `Authorization` header. In the commands below, replace `<API Key>` with your API key, `{projectKey}` with your project key or ID, and `{environmentKey}` with your environment key or ID.

### List the users in an environment \{#get-all-users}

This [curl](https://curl.se/) command lists the users in one environment:

```bash
curl -H "Authorization: Bearer <API Key>" https://api.permit.io/v2/facts/{projectKey}/{environmentKey}/users
```

The API returns HTTP 200 with a JSON object that contains the users. An HTTP 401 response means the `Authorization` header is missing or the API key is invalid.

### List the tenants in an environment \{#get-all-tenants}

This command lists the tenants in one environment:

```bash
curl -H "Authorization: Bearer <API Key>" https://api.permit.io/v2/facts/{projectKey}/{environmentKey}/tenants
```

## Call the API with Postman \{#using-postman}

1. Install [Postman](https://www.postman.com/downloads/).
2. Create a request to a Permit API endpoint, for example `https://api.permit.io/v2/facts/{projectKey}/{environmentKey}/users`.
3. On the **Authorization** tab, select **Bearer Token** as the auth type, and paste your API key.

![Postman Authorization tab with Bearer Token selected and a Permit API key in the Token field](/img/api_keys/postman.png)

To import every Permit endpoint into Postman at once, import the [OpenAPI spec](https://api.permit.io/v2/openapi.json).

## API endpoints and regions \{#api-endpoints-and-regions}

The examples in the Permit docs use the `api.permit.io` endpoint. If your workspace is hosted in the EU region, replace `api.permit.io` with `api.eu.permit.io` in every API call. Which regions you can choose depends on your plan; see [Permit pricing](https://www.permit.io/pricing).

### Set the region in the Node.js SDK \{#permit-init-example-on-node-sdk}

In the SDKs, set the API URL when you create the Permit client. In the Node.js SDK, set `apiUrl`:

```node
const permit = new Permit({
  // the API key to the Permit environment you wish to connect to
  token: "<YOUR_API_KEY>",
  // the url in which the SDK can connect to the PDP container
  pdp: "http://localhost:7766",
  // use this to turn on sdk logs
  log: {
    level: "debug",
  },
  // the region in which the Permit environment is located
  apiUrl: "https://api.eu.permit.io",
});

```

## Rate limiting \{#rate-limiting}

The Permit API rate-limits requests to protect the service. When a client exceeds a rate limit, the API returns **HTTP 429 Too Many Requests**. Retry the request after a delay, and increase the delay between retries if the API keeps returning 429. To send many changes in fewer requests, use the [bulk operations](/how-to/bulk-operations).

## Review API calls in the API log \{#working-with-the-api-logs}

Permit records every external API call in the API log, so you can inspect the request and response of a call that failed. The API log is per organization: it lists the calls made in the organization you are signed in to.

1. In the Permit dashboard, open **Settings** and select the **API Log** tab. Each row shows the timestamp of the call, the actor who made the call, the action (the endpoint that was called), and the response status.

   <video controls>
     <source src={apiLogs} />
   </video>

2. Click a call to open its **API Log Event**.

   <video controls>
     <source src={apiLogEvent} />
   </video>

3. Open the **Request** tab to see the payload sent to the endpoint, and the **Response** tab to see the data the endpoint returned.

:::tip Debug a failing call
When an API call fails, the **Response** tab shows the error message the API returned, such as a validation error that names the invalid field.
:::
