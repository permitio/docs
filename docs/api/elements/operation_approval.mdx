Require approval before a user performs a sensitive operation, and manage those approvals through the Permit Elements API. This page is for developers who build a custom approval flow on top of Permit Elements, the embeddable UI components. A user requests approval for an operation on a resource, and a reviewer approves or denies the request.

The requests on this page run as a user signed in to an element, with the session that your server-side login route creates. If you already added a login route for the [Access Request API](/api/elements/access-requests#server-side-login-route), skip to [Operation approval endpoints](#api-requests).

:::note Related resources
- For every endpoint and schema, see [Operation Approval](https://api.permit.io/v2/redoc#tag/Operation-Approval-(EAP)) in the API reference.
- For the embedded UI, see the [Operation Approval element](/embeddable-uis/element/operation-approval).
- For a working application that uses the Operation Approval API, see the [Mesa Verde banking demo](https://github.com/permitio/mesa-verde-banking-demo) on GitHub.
:::

## Prerequisites

- An environment API key, used to initialize the Permit SDK in your backend. See [Get your API key](/overview/get-api-key).
- The ID or key of your project and environment. See [Get the project and environment IDs](/api/examples/get-project-and-env).
- The ID of the Operation Approval element configuration, used as `elements_config_id`. See [List the elements in an environment](/api/elements/overview).

### Add a server-side login route \{#server-side-login-route}

Create a route in your backend that signs the current user in to the element with `loginAs`. Match the route to the authentication method your application uses, such as a bearer token or cookies.

The `loginAs` method takes the unique ID of the user, usually read from the user's JSON Web Token (JWT), and the key or ID of the tenant:

```js
permit.elements.loginAs({ userId, tenant });
```

:::info The user must belong to the tenant
If the user is not a member of the tenant passed to `loginAs`, the login fails with the error `USER_NOT_FOUND`.

The session applies to one tenant. To switch a user to a different tenant, sign the user out and call `loginAs` again with the other tenant.
:::

Passing the tenant is required for a server-side login.

## Operation approval endpoints \{#api-requests}

All paths start with `https://api.permit.io/v2/elements/{proj_id}/{env_id}/config/{elements_config_id}`. Replace `<COOKIE FROM LOGIN>` in the examples with the session cookie from the login route.

| Method | Path suffix | Operation | Who calls it |
|---|---|---|---|
| `POST` | `/operation_approval` | [Create an operation approval](#creating-an-approval-request) | Requesting user |
| `GET` | `/operation_approval/{operation_approval_id}` | [Get an operation approval](#1-get-an-operation-approval) | Reviewer |
| `GET` | `/operation_approval` | [List operation approvals](#2-get-all-the-approval-requests) | Reviewer, or a user for their own approvals |
| `PATCH` | `/operation_approval/{operation_approval_id}/reviewer` | [Update the reviewer comment](#3-updating-reviewer-details-in-the-operation-approval) | Reviewer |
| `PUT` | `/operation_approval/{operation_approval_id}/approve` | [Approve an operation approval](#4-approve-operation-approval) | Reviewer |
| `PUT` | `/operation_approval/{operation_approval_id}/deny` | [Deny an operation approval](#5-deny-operation-approval) | Reviewer |
| `PUT` | `/operation_approval/{operation_approval_id}/cancel` | [Cancel an operation approval](#1-cancel-operation-approval) | Requesting user |

An operation approval has one of these `status` values: `pending`, `approved`, `denied`, or `canceled`.

## Create an operation approval \{#creating-an-approval-request}

Send a `POST` request to `/operation_approval` with the details of the operation.

| Field | Required | Description |
|---|---|---|
| `access_request_details.tenant` | Yes | ID or key of the tenant the operation runs in |
| `access_request_details.resource` | Yes | ID or key of the resource the operation applies to |
| `access_request_details.resource_instance` | No | ID or key of the resource instance the operation applies to |
| `reason` | No | Business justification from the requesting user |

```bash
curl -X POST \
 'https://api.permit.io/v2/elements/{proj_id}/{env_id}/config/{elements_config_id}/operation_approval' \
  -H 'cookie: <COOKIE FROM LOGIN>'
  -H 'element_id: ELEMENTS_CONFIG_ID'
  -data-raw
 {
     "access_request_details": {
            "tenant": "34f5c98e-f430-457b-a812-92637d0c6fd0",
            "resource": "4d5215ed-38bb-48ed-879a-fdb9ca58522f",
        },
    "reason": "I need to make transfer for my client",
 } \
```

The API returns the created operation approval, with `type` set to `operation_approval`:
```json
{
    "requesting_user_id": "1c1e4ada-f282-40e6-b3b7-20b3a51c93b5",
     "access_request_details": {
        "tenant": "34f5c98e-f430-457b-a812-92637d0c6fd0",
        "resource": "4d5215ed-38bb-48ed-879a-fdb9ca58522f",
        "resource_instance": "2d98d9f8-e1b7-4f1d-baad-2edbf6fa6c66",
    },
    "reason": "I need to make transfer for my client",
    "org_id": "7c60d51f-b44e-4682-87d6-449835ea4de6",
    "project_id": "405d8375-3514-403b-8c43-83ae74cfe0e9",
    "env_id": "40ef0e48-a11f-4963-a229-e396c9f7e7c4",
    "created_at": "2019-08-24T14:15:22Z",
    "updated_at": "2019-08-24T14:15:22Z",
    "status": null,
    "reviewer_user_id": null,
    "reviewed_at": null,
    "reviewer_comment": null,
    "type": "operation_approval"
}
```

The response includes the approval's `id`, which you pass as `{operation_approval_id}` in the other calls.

### List operation approvals \{#2-get-all-the-approval-requests}

Send a `GET` request to `/operation_approval`. Filter and paginate the list with these query parameters:

| Query parameter | Description |
|---|---|
| `status` | Only approvals with this status: `pending`, `approved`, `denied`, or `canceled` |
| `resource` | Only approvals for this resource |
| `resource_instance` | Only approvals for this resource instance |
| `page` | Page number, starting at 1. Default `1`. |
| `per_page` | Results per page, maximum 100. Default `30`. |

```bash
curl 'https://api.permit.io/v2/elements/{proj_id}/{env_id}/config/{elements_config_id}/operation_approval' \
  -H 'cookie: <COOKIE FROM LOGIN>'
  -H 'element_id: ELEMENTS_CONFIG_ID'
  -H 'status: Status of the approval process'
  -H 'resource: Resource key of the approval process'
  -H 'resource_instance: Resource instance key of the approval process'
  -H 'page: Page number of the results to fetch' #Default: 1
  -H 'per_page: The number of results per page (max 100)' #Default: 30
```

The API returns a page of operation approvals. Each item also includes the requesting user's email, first name, and last name, and the resource and resource instance keys:

## Requesting user actions \{#users-actions}

### Cancel an operation approval \{#1-cancel-operation-approval}

Send a `PUT` request to `/operation_approval/{operation_approval_id}/cancel`. The request has no body.

```bash
curl -X PUT \
 'https://api.permit.io/v2/elements/{proj_id}/{env_id}/config/{elements_config_id}/operation_approval/{operation_approval_id}/cancel' \
  -H 'cookie: <COOKIE FROM LOGIN>'
  -H 'element_id: ELEMENTS_CONFIG_ID'
  --data-raw
{
    "reason": "done onboarding last week",
} \
```
