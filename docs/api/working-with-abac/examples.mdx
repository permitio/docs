Build a complete attribute-based access control (ABAC) policy with the Permit API: one user set, one resource set, and one condition set rule. This page is for developers who have read [Create condition sets with the API](/api/working-with-abac/condition-sets) and want a worked example to adapt.

## Example policy: full-time students rent bicycles after 5 PM \{#example}

### Policy statement \{#students-that-study-at-stanford-university-and-are-not-part-of-the-part-time-study-scheme-can-rent-university-bicycles-after-5pm}

Students who are not in the part-time study scheme can rent university bicycles after 5 PM.

The policy breaks down into three parts:

| Part | Definition | Key |
|---|---|---|
| **User set** | Users with the `student` role whose `education` attribute is not `part-time` | `full_time_stanford_students` |
| **Action** | Rent a bicycle | `bicycle:rent` |
| **Resource set** | Resources of type `bicycle` whose `availability` is 17 (5 PM) or later | `rent_bicycle_after_5` |

## Prerequisites

- An environment API key. See [Get your API key](/overview/get-api-key).
- A `bicycle` resource with a `rent` action, and an `availability` resource attribute of type number.
- A user attribute `education` and a `student` role.

## 1. Create the user set \{#user-set}

Send the following body in a `POST` request to `https://api.permit.io/v2/schema/{proj_id}/{env_id}/condition_sets`. The `allOf` operator requires both conditions: the user has the `student` role, and the user's `education` attribute is not `part-time`.

```bash title="full_time_students_after_5"
curl 'https://api.permit.io/v2/schema/{proj_id}/{env_id}/condition_sets' \
  -X POST \
  -H 'Authorization: Bearer <YOUR_API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{
    "key": "full_time_students_after_5",
    "name": "Full-time Stanford students after 5 PM",
    "type": "userset",
    "conditions": {
        "allOf": [
            {"user.university": {"equals": "Stanford"}},
            {"user.is_full_time": {"equals": true}},
            {"user.current_hour": {"greater-than-equals": 17}}
        ]
    }
}'
```

## 2. Create the resource set \{#resource-set}

Send the following body to the same endpoint. The conditions match resources of type `bicycle` whose `availability` attribute is greater than or equal to 17.

```bash title="university_bicycles"
curl 'https://api.permit.io/v2/schema/{proj_id}/{env_id}/condition_sets' \
  -X POST \
  -H 'Authorization: Bearer <YOUR_API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{
    "key": "university_bicycles",
    "name": "University bicycles",
    "type": "resourceset",
    "resource_id": "bicycle",
    "conditions": {
        "allOf": [
            {"resource.owner": {"equals": "university"}}
        ]
    }
}'
```

## 3. Create the condition set rule

Send the following body in a `POST` request to `https://api.permit.io/v2/facts/{proj_id}/{env_id}/set_rules`. The rule grants `bicycle:rent` to the user set on the resource set.

```bash title="bicycle:rent set rule"
curl 'https://api.permit.io/v2/facts/{proj_id}/{env_id}/set_rules' \
  -X POST \
  -H 'Authorization: Bearer <YOUR_API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{
    "user_set": "full_time_students_after_5",
    "permission": "bicycle:rent",
    "resource_set": "university_bicycles"
}'
```

## 4. Verify the policy

Send a `GET` request to `https://api.permit.io/v2/facts/{proj_id}/{env_id}/set_rules?user_set=full_time_stanford_students`. The response lists a rule with `permission` set to `bicycle:rent` and `resource_set` set to `rent_bicycle_after_5`.

To test the policy with real users and resources, run a permission check as described in [Check permissions](/how-to/enforce-permissions/check).
