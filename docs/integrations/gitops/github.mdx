Connect a GitHub repository to a Permit.io project so that Permit writes the policy code of each environment to the repository and syncs your changes to your policy decision points (PDPs). This page is for developers who set up GitOps with the Permit API. For what GitOps does, see the [GitOps overview](/integrations/gitops/overview).

The setup has two parts:

1. Add an SSH deploy key with write access to your GitHub repository.
2. Register the repository in Permit with the repository's SSH URL and the private key, then activate the repository.

:::tip Use the Permit CLI instead
The [`permit gitops create github`](/how-to/permit-cli/permit-cli-gitops#sync-policies-to-git-repositories) command of the Permit CLI runs the same setup as an interactive wizard: it generates the SSH key pair, asks for the repository details, and registers the repository in Permit.
:::

:::info Other Git providers
The same steps work with other Git providers that support SSH deploy keys, with provider-specific changes to the deploy key step:

- [Add a deploy key in GitLab](https://docs.gitlab.com/ee/user/project/deploy_keys/)
- [Add an SSH key in Bitbucket](https://support.atlassian.com/bitbucket-cloud/docs/set-up-an-ssh-key/)
:::

## Prerequisites

- A Permit.io account with a project. Permit maps each repository to one project.
- A GitHub repository you can change settings for, or permission to create one.
- `ssh-keygen`, `awk`, and `curl` on your machine.
- An Edge PDP if you plan to add custom Rego. The Cloud PDP doesn't run custom policy code. See [Cloud PDP capabilities](/concepts/pdp/cloud-pdp-capabilities#supported-policy-models).

## Add an SSH deploy key to the repository \{#add-ssh-deploy-key}

Permit pushes generated policy code to your repository over SSH. Give Permit access with a deploy key that has write access.

### Create a repository with an initial commit \{#create-a-repository}

Permit needs a repository whose default branch exists on the remote, with at least one commit. If you already have such a repository, go to [Generate an SSH key](#generating-an-ssh-key).

Create the repository in [GitHub](https://github.com/new), and add at least one file, such as a README, so the default branch has a commit.

![The GitHub Create a new repository form](/img/integrations/gitops/github-new-repo.png)

:::warning Empty repositories fail to clone
If the default branch of the repository has no commits, Permit can't clone the branch. This also applies when you use the [Copy Environment API](https://api.permit.io/v2/redoc#tag/Environments/operation/copy_environment) with GitOps. Commit at least one file before you continue.
:::

Permit maps each repository to one Permit project. For each environment in the project, Permit creates and maps a branch in the repository.

### Generate an SSH key \{#generating-an-ssh-key}

Generate an SSH key pair on your machine:

```bash
ssh-keygen -t ecdsa -b 521 -C "help@permit.io"
```

`ssh-keygen` asks for a file location and a passphrase. Leave the passphrase empty: the Permit API accepts a private key without a passphrase field.

![Terminal output of ssh-keygen generating an ECDSA key pair](/img/integrations/gitops/generate-ssh-key.png)

The private key is saved at the location you chose. The public key is saved at the same location with a `.pub` suffix. You send the private key to Permit in a later step, so keep it out of your repositories.

### Add the public key as a deploy key \{#adding-the-deploy-key}

1. In your GitHub repository, go to **Settings** > **Deploy keys** and click **Add deploy key**.

   ![The Deploy keys page in GitHub repository settings, with the Add deploy key button](/img/integrations/gitops/github-add-deploy-key-1.png)

2. Paste the contents of the public key file (the `.pub` file) from [Generate an SSH key](#generating-an-ssh-key).

3. Select **Allow write access**, then click **Add key**. Without write access, Permit can't push the generated policy branches.

   ![The Add deploy key form in GitHub with the Allow write access checkbox selected](/img/integrations/gitops/github-add-deploy-key-2.png)

## Register the repository in Permit \{#permit-gitops-configuration}

Register the repository with the Permit API, then activate the repository.

### Create the repository configuration file \{#creating-a-json-configuration-file}

Create a JSON file with this structure. The next sections fill in each placeholder.

```json
{
  "url": "<your-ssh-url>",
  "main_branch_name": "<your-default-branch>",
  "credentials": {
    "auth_type": "ssh",
    "username": "git",
    "private_key": "<your-private-key>"
  },
  "key": "<your-custom-id-string-without-spaces>"
}
```

| Field | Value |
|---|---|
| `url` | The SSH URL of the repository, such as `git@github.com:acme-corp/policy.git`. |
| `main_branch_name` | The default branch of the repository. The API default is `main`. |
| `credentials.private_key` | The private key from [Generate an SSH key](#generating-an-ssh-key), on one line. |
| `key` | A name you choose for the repository configuration. Letters, digits, `-`, and `_` only. You use the key later to activate the repository. |

### Add the SSH details from GitHub \{#copy-the-ssh-details-from-github}

1. In GitHub, click **Code**, select the **SSH** tab, and copy the SSH URL. Replace `<your-ssh-url>` in the JSON file with the URL.

   ![The GitHub Code menu with the SSH clone URL selected](/img/integrations/gitops/github-copy-ssh-url.png)

2. Print the private key with each new line replaced by `\n`, and replace `<your-private-key>` with the output. Replace `<private-key-file>` with the path of the private key file:

   ```shell
   awk -v ORS='\\n' '1' <private-key-file>
   ```

3. Replace `<your-default-branch>` with the default branch name of your repository, such as `main`.

### Get your project key from Permit \{#get-your-project-key--id-from-permit}

The repository API calls in this guide use a project or organization API key.

1. Sign in to [Permit](https://app.permit.io).

2. Select your project in the project selector in the sidebar.

3. Go to the [API Keys](https://app.permit.io/settings/api-keys) page and create a project or organization API key. For the differences between key levels, see [API key levels](/manage-your-account/workspace-settings#api-keys).

   ![The API Keys page in Permit settings](/img/integrations/gitops/permit-settings-api-keys.png)

4. List your projects. Replace `<your-permit-api-key>` with the API key you created:

   ```shell
   curl -X GET "https://api.permit.io/v2/projects" -H "Content-Type: application/json" -H "Authorization: Bearer <your-permit-api-key>"
   ```

5. Copy the `key` or `id` of your project from the response. For more detail, see [Get project ID or key](/api/examples/get-project-and-env/#get-project-id-or-key).

### Register and activate the repository \{#configure-permit-to-use-your-repository}

1. Send the JSON file to Permit. Replace `<your-project-id-or-key>` with your project key, `<your-permit-api-key>` with the project or organization API key you created, and `path/to/your/json` with the path of the JSON file:

   ```shell
   curl -X POST "https://api.permit.io/v2/projects/<your-project-id-or-key>/repos" -H "Content-Type: application/json" -H "Authorization: Bearer <your-permit-api-key>" --data-binary @"path/to/your/json"
   ```

2. In your GitHub repository, check the branch list. Permit creates one branch per environment of the project, named `permit/generated/<env_id>`, where `<env_id>` is the ID of the environment.

   To use a different branch name for an environment, set the environment's custom branch name. See [Customize the GitOps branch name](/manage-your-account/creating-environments#customize-gitops-branch-name).

3. Activate the repository. Replace `<your-project-id-or-key>` with your project key, `<your-repo-id-or-key>` with the `key` from your JSON file, and `<your-permit-api-key>` with the same API key:

   ```shell
   curl -X PUT "https://api.permit.io/v2/projects/<your-project-id-or-key>/repos/<your-repo-id-or-key>/activate" -H "Authorization: Bearer <your-permit-api-key>"
   ```

### Verify the repository connection \{#verify-the-repository-connection}

Send a `GET` request to `https://api.permit.io/v2/projects/<your-project-id-or-key>/repos/active` with the same API key. The response is the active repository of the project and includes the repository's `key`, `url`, and `status`. The `status` is one of `pending`, `valid`, or `invalid`.

If the request returns no active repository, or `status` is `invalid`, check that the deploy key has write access, that the private key in the JSON file matches the public deploy key, and that the default branch has at least one commit.

## Test the connection with a custom policy \{#test-your-configuration}

1. Check out an environment branch, `permit/generated/<env_id>`.

2. Add your Rego code in the `custom` folder only. Either edit `custom/root.rego`, or create a file in the `custom` folder and reference its package from `custom/root.rego`. For a worked example, see [Write custom policies with GitOps](/integrations/gitops/custom_policy).

   :::danger Keep your code in the custom folder
   Permit generates the files outside the `custom` folder. If you edit a generated file, Permit can overwrite your change when it regenerates the policy, or your change can break the generated Rego. The one edit outside `custom` that Permit's generated comments describe is combining the `allow` rules in the top-level `root.rego`, covered in [Enforce the deny rule](/integrations/gitops/custom_policy#enforce-the-deny-policy).
   :::

3. Commit your change and push the environment branch to GitHub. Push to the environment branch, not the main branch. Permit detects the push and sends the updated policy to the PDPs of that environment.

4. Run a permission check that your custom rule affects, such as a [`permit.check()` call](/how-to/enforce-permissions/check), against an Edge PDP of that environment. The result reflects your custom rule.
