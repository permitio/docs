Write a Node.js script that defines your resources and roles in code and applies them to a Permit.io environment with the Node.js SDK. The script creates each resource and role that doesn't exist yet, and updates the permissions of roles that already exist. You can run the script again after you change the definitions. This guide is for backend developers who keep the policy schema in source control instead of editing it in the Permit dashboard.

## Prerequisites

- Node.js and a project with the `permitio` package installed. See [Install the Permit.io SDK](/sdk/nodejs/quickstart-nodejs#1-install-the-permitio-sdk).
- An API key for the environment that the script changes. See [Get your API key](/overview/get-api-key).

## Structure of the policy script \{#steps-to-use-the-script}

The script has four parts. The code blocks in this section show the outline of each part. The [full policy script](#attached-the-full-code-for-reference) fills in every part.

### 1. Create a Permit client

Import the SDK and create a `Permit` client. Replace `permit_key_` with your API key. The script calls the Permit API, which uses the API key to select the environment.

```javascript
const { Permit } = require('permitio');
const permit = new Permit({
    pdp: 'https://cloudpdp.api.permit.io',
    token: 'permit_key_',
});
```

### 2. Define resources and roles \{#define-resources-and-roles}

Define two arrays. Each item in `resources` is a `ResourceCreate` object with `key`, `name`, and `actions`. Each item in `roles` is a `RoleCreate` object with `key`, `name`, and `permissions` in the format `resource:action`. See [Create a resource with the Node.js SDK](/sdk/nodejs/resource/create-resource) and [Create a role with the Node.js SDK](/sdk/nodejs/role/create-role) for all fields.

```javascript
const resources = [
    // Define resources here
];

const roles = [
    // Define roles here
];
```

### 3. Write the createPolicy function \{#create-policy-function}

The `createPolicy` function loops over both arrays. For each item, the function checks whether the resource or role exists, and creates or updates it.

```javascript
const createPolicy = async () => {
    // Implementation here
};
```

### 4. Run the script \{#running-the-script}

Call `createPolicy` and log the result. The script prints `done` when every resource and role is applied, and prints the error otherwise.

```javascript
createPolicy().then(() => {
    console.log("done");
}).catch((err) => {
    console.log(err);
});
```

## Full policy script \{#attached-the-full-code-for-reference}

The full script defines three resources (`employee`, `task`, and `folder`) with `create`, `read-all`, `delete`, and `export` actions, and a `manager` role. For each resource and role, the script works as follows:

| Item | Exists in Permit | What the script does |
|---|---|---|
| Resource | No | Creates the resource with `permit.api.resources.create()`. |
| Resource | Yes | Logs `resource already exists` and leaves the resource unchanged. The script doesn't update the actions of an existing resource. |
| Role | No | Creates the role with `permit.api.roles.create()`. |
| Role | Yes, with the same permissions | Logs `permissions for role: <key> are up to date`. |
| Role | Yes, with different permissions | Removes the current permissions with `permit.api.roles.removePermissions()`, then adds the defined permissions with `permit.api.roles.assignPermissions()`. |

The script treats any error from `permit.api.resources.get()` or `permit.api.roles.get()` as "doesn't exist" and tries to create the item.

```js
const { Permit } = require('permitio');

// Create a Permit client. The script only calls the Permit API.
const permit = new Permit({
    // in production, you might need to change this url to fit your deployment
    pdp: 'https://cloudpdp.api.permit.io',
    // your api key
    token:
        'permit_key_',
});


const roles = [
    {
        "key": "manager",
        "name": "Manager",
        "description": "Default User",
        "permissions": ["employee:export", "employee:delete"]
    },
]

const resources = [
    {
        "key": "employee",
        "name": "Employee",
        "actions": {
            "create": {
                "name": "create",
            },
            "read-all": {
                "name": "read-all"
            },
            "delete": {
                "name": "delete"
            },
            "export": {
                "name": "export"
            },
        },
    },
    {
        "key": "task",
        "name": "Task",
        "actions": {
            "create": {
                "name": "create",
            },
            "read-all": {
                "name": "read-all"
            },
            "delete": {
                "name": "delete"
            },
            "export": {
                "name": "export"
            },
        },
    
    },
    {
        "key": "folder",
        "name": "Folder",
        "actions": {
            "create": {
                "name": "create",
            },
            "read-all": {
                "name": "read-all"
            },
            "delete": {
                "name": "delete"
            },
            "export": {
                "name": "export"
            },
        },
    }
]


const createPolicy = async () => {
    // iterate through resources
    for (let resource of resources) {
        // check if resource exists
        let resourceExists
        try {
            resourceExists = await permit.api.resources.get(resource.key);
        } catch(err){
            console.log('no resource: ' + resource.key);
        }

        // if resource don't exist create it
        if (!resourceExists) {
            console.log("creating resource: " + resource.key);
            await permit.api.resources.create(resource);
        } else {
            console.log("resource already exists: " + resource.key);
        }
    }
    // iterate through roles
    for (let role of roles) {
        // check if role exists
        let roleExists
        try {
            roleExists = await permit.api.roles.get(role.key);
        } catch(err){
            console.log('no role: ' + role.key);
        }
        // if role don't exist create it
        if (!roleExists) {
            console.log("creating role: " + role.key);
            await permit.api.roles.create(role);
        } else {
            console.log("role already exists: " + role.key);
            console.log(roleExists.permissions, role.permissions)
            if (roleExists.permissions.some(x => !role.permissions.includes(x)) || role.permissions.some(x => !roleExists.permissions.includes(x))) {
                console.log("updating permissions for role: " + role.key);
                // clear permissions
                await permit.api.roles.removePermissions(roleExists.id, roleExists.permissions);
                // add permissions
                await permit.api.roles.assignPermissions(roleExists.id, role.permissions);
            } else {
                console.log("permissions for role: " + role.key + " are up to date");
            }
        }
    }
}

createPolicy().then(() => {
    console.log("done");
}
).catch((err) => {
    console.log(err);
}
)
```

## Verify the policy script \{#notes}

1. Save the full script as `sync-policy.js` and run `node sync-policy.js`. The first run logs `creating resource: employee`, `creating resource: task`, `creating resource: folder`, `creating role: manager`, and `done`.
2. Run the script a second time. The second run logs `resource already exists` for each resource, `permissions for role: manager are up to date`, and `done`.
3. In the Permit dashboard, open the Policy Editor. The `employee`, `task`, and `folder` resources and the `manager` role appear, and `manager` has the `export` and `delete` permissions on `employee`.
