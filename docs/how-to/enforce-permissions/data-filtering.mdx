Return only the data a user is allowed to see, instead of a single allow or deny decision. This page is for backend developers who query lists of records, such as documents or projects, and must drop the records a user can't access. It compares the filtering approaches Permit supports and shows how to filter a list of objects with `FilterObjects()`.

## Prerequisites

- A Permit SDK client connected to a policy decision point (PDP) ([Run the PDP](/overview/run-pdp))
- A policy with resource instances or attributes that decide which records a user can access

## Choose a data filtering approach

There are two ways to authorize access to data from a database:

- **Boolean query filtering** decides whether a query may run at all. Map the query to a resource and an action, then run a standard [`permit.check()`](/how-to/enforce-permissions/check). For example, parse a SQL or Couchbase N1QL query into resources and actions ([Couchbase example](https://www.couchbase.com/blog/permit-io-couchbase-access-control/)).
- **Data filtering** runs the query and returns only the records the user can access. Pick one of the approaches in the following table.

| Approach | Where filtering happens | How it works | Permit functions |
|---|---|---|---|
| Application-level filtering | Your application, after the query | Fetch the records, send one bulk check for all of them, and keep the records whose result is `true`. | [`permit.bulkCheck()`](/how-to/enforce-permissions/bulk-check#data-filtering) |
| Object filtering with `filterObjects` | The SDK, after the query | Fetch the records and pass them to `filterObjects`. The SDK sends one bulk check and returns the allowed subset. | `FilterObjects()` (Go), `filter_objects()` (Python) |
| Pre-filtering from the permissions graph | Your application, before the query | Ask the PDP which objects the user can access, and add the allowed keys to the query's `WHERE` clause. | [`getUserPermissions()`](/how-to/enforce-permissions/user-permissions), [`authorized_users()`](/how-to/enforce-permissions/authorized-users) |
| Source-level filtering (partial evaluation) | The database | Ask Open Policy Agent (OPA) for the conditions a record must meet, translate the conditions into a query filter, and run the filtered query. | OPA's [Compile API](https://www.openpolicyagent.org/docs/latest/rest-api/#compile-api), through the PDP's [exposed OPA port](/how-to/deploy/deploy-to-production#exposing-opa-within-the-pdp) |

Application-level filtering and `filterObjects` send a check for every record the query returns, so they suit result sets you already page or limit. Pre-filtering and source-level filtering keep unauthorized records out of the query result.

## Filter a list of objects with FilterObjects() \{#pdp-level-filtering}

`FilterObjects()` takes a user, an action, a request context, and the resources to filter. It returns the resources the user can perform the action on, in their original order.

Replace `<YOUR_API_KEY>` with your environment API key ([Get your API key](/overview/get-api-key)).

```go
package main

import (
	"fmt"
)
import p "github.com/permitio/permit-golang/pkg/permit"
import "github.com/permitio/permit-golang/pkg/config"
import "github.com/permitio/permit-golang/pkg/enforcement"

func main() {
	// Create permit client
	permitConfig := config.NewConfigBuilder("<YOUR_API_KEY>").Build()
	permit := p.New(permitConfig)

	requestContext := map[string]string{
		"source": "docs",
	}
	user := enforcement.UserBuilder("john@doe.com").Build()
	var action enforcement.Action = "read"
	resourcesToCheck := []enforcement.ResourceI{
		enforcement.ResourceBuilder("document").WithID("document-1").WithTenant(enforcement.DefaultTenant),
		enforcement.ResourceBuilder("folder").WithID("folder-1").WithTenant(enforcement.DefaultTenant),
		enforcement.ResourceBuilder("document").WithID("document-2").WithTenant(enforcement.DefaultTenant),
		enforcement.ResourceBuilder("document").WithID("document-3").WithTenant(enforcement.DefaultTenant),
	}
	var allowedResources []enforcement.ResourceI
	var err error
	// Filter the objects
	allowedResources, err = permit.FilterObjects(user, action, requestContext, resourcesToCheck...)
	if err != nil {
		fmt.Printf("Error enforcing permissions: %s", err)
	} else {
		// The response indexes correspond to the request indexes
		for i, resource := range allowedResources {
			fmt.Printf("%d. User '%s' is PERMITTED to '%s' a '%s' with id '%s'\n",
				i, user.Key, action, resource.GetType(), resource.GetID(),
			)
		}
	}
}

```

## Verify the filter result

For each allowed resource, the example prints one line, for example `0. User 'john@doe.com' is PERMITTED to 'read' a 'document' with id 'document-1'`.

Resources the policy denies don't appear in the output. If no line prints, John has no `read` permission on any of the four resources.
