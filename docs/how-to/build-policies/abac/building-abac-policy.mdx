Build an attribute-based access control (ABAC) policy in the Permit.io dashboard, then confirm it with a `permit.check()` call. This tutorial is for developers who have built a role-based policy in Permit and need rules based on user and resource attributes.

## Prerequisites

- A Permit.io account with a project and an environment. See the [Quickstart](/quickstart).
- To run the check at the end: your environment API key ([Get your API key](/overview/get-api-key)) and a Permit SDK connected to a policy decision point (PDP). See [Check permissions with permit.check()](/how-to/enforce-permissions/check).
- Familiarity with user sets and resource sets. See the [ABAC overview](/how-to/build-policies/abac/overview).

## Example scenario \{#our-example-scenario}

The tutorial builds this policy:

:::info Example policy
**"Only full-time students at Stanford University can rent university bicycles after 5pm."**
:::

The policy uses these attributes and actions:

| Part | Name | Type |
|---|---|---|
| User attribute | `university` | String |
| User attribute | `is_full_time` | Boolean |
| Resource attribute | `time` (hour of the day) | Number |
| Actions | `rent`, `ride` | |

<TimelineWrapper>
<TimelineStep>

### Step 1: Create user attributes \{#step-1-creating-user-attributes}

User attributes describe your users, such as their university or employment status.

1. Open the **Directory** screen.
2. Click **Settings**.
3. Select **User Attributes**, then click **Add Attribute**.

![Directory Settings panel with User Attributes selected, listing the built-in roles, email, and key attributes, and the Add Attribute button](/img/abac-updated/user-attributes-0.png)

4. Add the two user attributes for the bicycle rental example:
   - `university` (string): the university the student attends.
   - `is_full_time` (bool): whether the student is enrolled full-time.
5. Click **Save**.

![User Attributes list with the university string attribute and the is_full_time bool attribute added](/img/abac-updated/user-attributes-1.png)

</TimelineStep>

<TimelineStep>

### Step 2: Create tenant attributes (optional) \{#step-2-creating-tenant-attributes}

Tenant attributes describe a whole tenant, such as a customer organization. The bicycle policy doesn't need tenant attributes. Add them when your rules depend on the tenant, for example on its subscription plan.

1. On the **Directory** screen, click **Settings**.
2. Select **Tenant Attributes**, then click **Add Attribute**.

![Directory Settings panel with Tenant Attributes selected and the Add Attribute button](/img/abac-updated/tenant-attributes-0.png)

Example tenant attributes:

- `is_paying`: whether the tenant has an active subscription.
- `tier`: the service tier.
- `user_count`: the number of licensed users.

![Tenant Attributes list with example attributes added](/img/abac-updated/tenant-attributes-1.png)

3. Click **Save**.

</TimelineStep>

<TimelineStep>

### Step 3: Define a dynamic role (user set) \{#step-3-defining-dynamic-role-user-set}

A dynamic role (user set) is a group of users whose attributes match a set of conditions. A user joins or leaves the user set when their attribute values change.

1. Open the **Policy** screen and select the **ABAC Rules** tab.

![ABAC Rules tab with the ABAC Dynamic Role (User Sets) and ABAC Dynamic Resource (Resource Sets) sections, each with a Create New button](/img/abac-updated/abac-sets.png)

2. In **ABAC Dynamic Role (User Sets)**, click **Create New**.
3. Name the user set `Full-time Stanford Student`.
4. Click **Add Condition** and add these conditions:
   - `user.university` equals `Stanford`
   - `user.is_full_time` equals `true`
5. Save the user set.

![Dynamic Role (User Set) form named Full-time Stanford Student with two conditions joined by and: university equals Stanford and is_full_time equals True](/img/abac-updated/user-set-0.png)

:::warning Tenant boundaries in user sets
Permit doesn't enforce tenant boundaries for user sets. A user who matches the conditions of a user set matches it in every tenant, so the user set grants its permissions on resources in other tenants too. To keep a user set inside a tenant, do one of the following:

- Add a condition on `user.roles`.
- Use tenant attributes, and compare them with `resource.tenant` in the resource set.
:::

</TimelineStep>

<TimelineStep>

### Step 4: Create the bicycle resource \{#step-4-creating-resources}

A resource is an object type you want to protect. Each resource has actions and can have attributes.

1. Open the **Policy** screen and select the **Resources** tab.
2. Click **Add Resource**.
3. Name the resource `bicycle`.
4. Add the actions `ride` and `rent`.
5. Under **ABAC Options**, add the attribute `time` with the type **Number**.
6. Click **Save**.

![New Resource panel for the bicycle resource](/img/abac-updated/resource-attributes-0.png)
![ABAC Options of the bicycle resource with the time attribute of type Number](/img/abac-updated/resource-attributes-1.png)

![The bicycle resource with its actions and the time attribute](/img/abac-updated/resource-attributes-3.png)

</TimelineStep>

<TimelineStep>

### Step 5: Define a dynamic resource (resource set) \{#step-5-defining-dynamic-resource-resource-set}

A dynamic resource (resource set) is a group of resources whose attributes match a set of conditions. For the example, create a resource set of bicycles available after 5pm.

1. On the **ABAC Rules** tab, in **ABAC Dynamic Resource (Resource Sets)**, click **Create New**.
2. Name the resource set `Bicycle available after 5pm`, and select the `bicycle` resource type.
3. Add the condition `resource.time` greater-than `17`.
4. Save the resource set.

![Dynamic Resource (Resource Set) form named Bicycle available after 5pm for the bicycle resource type, with the condition resource.time greater-than 17](/img/abac-updated/resource-set-0.png)

The **ABAC Rules** tab lists the user set and the resource set:

![ABAC Rules tab listing the Full-time Stanford Student user set and the bicycle resource set](/img/abac-updated/abac-sets-complete.png)

### Advanced: Compare resource and user attributes \{#advanced-comparing-resource-and-user-attributes}

A condition can compare a resource attribute with a user attribute instead of a fixed value. Use an operator that ends with `(ref)`, such as `equals (ref)`, and select the other attribute as the value.

![Resource set condition that compares a resource attribute with a user attribute using a ref operator](/img/abac/resource-user-condition.png)

</TimelineStep>

<TimelineStep>

### Step 6: Grant permissions \{#step-6-applying-permissions}

Connect the user set to the resource set with permissions.

1. Open the **Policy** screen and select the **Policy Editor** tab.
2. Find the `Full-time Stanford Students` user set.
3. In the column of the `Bicycles available after 5pm` resource set, select `rent` and `ride`.
4. Save your changes.

![Policy Editor with rent and ride selected for the Full-time Stanford Students user set on the Bicycles available after 5pm resource set](/img/abac-updated/policy-screen-check.png)

</TimelineStep>
</TimelineWrapper>

:::warning Reserved attribute key
You can't use `type` as the key of an attribute, because `type` is a reserved keyword.
:::

## Check the policy

Call `permit.check()` with the attribute values. In the following examples, the user and resource attributes are passed in the call as just-in-time attributes:

| User attributes | Resource attributes | Action | Result |
|---|---|---|---|
| `university: "Stanford"`, `is_full_time: true` | `time: 18` | `rent` | `true` |
| `university: "Stanford"`, `is_full_time: false` | `time: 18` | `rent` | `false` |
| `university: "Stanford"`, `is_full_time: true` | `time: 12` | `rent` | `false` |

For example, the first row is `permit.check({ key: "john@permit.io", attributes: { university: "Stanford", is_full_time: true } }, "rent", { type: "bicycle", attributes: { time: 18 } })`.

To store attribute values on users and resources instead, see [Defining attributes](/how-to/build-policies/abac/defining-attributes). For more on passing attributes in a check, see [Check permissions with permit.check()](/how-to/enforce-permissions/check).
