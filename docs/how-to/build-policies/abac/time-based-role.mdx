Grant a user a role that expires at a set time, per tenant, with an attribute-based access control (ABAC) user set (condition set) in Permit.io. This guide is for developers who need temporary access, such as an admin role for a support session, without removing the role assignment when the time is up.

## How the time-based role works

- The user has the `admin` role and a `time_based_groups` user attribute. Each entry in `time_based_groups` names a role, a tenant, and an expiration time.
- Your application passes the current time as the `current_time` user attribute in each `permit.check()` call.
- The `temp-admin` user set matches the user when the user has the `admin` role, and an entry in `time_based_groups` has an `expires` value greater than or equal to `current_time` and a `tenant` value equal to the tenant of the check.
- When the expiration time passes, the user set stops matching, and the check returns `false`.

## Prerequisites

- A [Permit.io](https://app.permit.io) account.
- A **role** with the key `admin`.
- A **resource** with the key `internal_api`, with the actions you want to grant temporarily. The check in this guide uses the `patch` action.
- Your environment API key. See [Get your API key](/overview/get-api-key).

2. Create the `time_based_groups` attribute.
3. Don't assign a value to a user yet.

![User Attributes settings with the time_based_groups attribute](/img/abac/time_based_groups.png)

### Create the condition set \{#create-condition-set}

The `temp-admin` condition set is a user set that matches a user based on:

- The user's role (`admin`).
- The expiration time in `time_based_groups`, compared with `current_time`.
- The tenant in `time_based_groups`, compared with the tenant's `key` attribute.

Create the condition set with the Permit API. The URL path contains the project key `default` and the environment key `production`: replace them with your project and environment keys. Replace `permit_key_` with your environment API key.

```bash
curl --location 'https://api.permit.io/v2/schema/default/production/condition_sets' \
--header 'Content-Type: application/json' \
--header 'Accept: application/json' \
--header 'Authorization: Bearer permit_key_' \
--data '{
  "key": "temp-admin",
  "name": "Temporary Admin",
  "type": "userset",
  "conditions": {
    "allOf": [
      {
        "allOf": [
          { "user.roles": { "array_contains": "admin" } },
          { "user.time_based_groups": { "any_match": { "match": {
            "expires": { "greater-than-equals": { "ref": "user.current_time" } },
            "tenant": { "equals": { "ref": "tenant.key" } }
          }}}}
        ]
      }
    ]
  }
}'
```

The API responds with the created condition set.

</TimelineStep>
<TimelineStep>

## Step 2: Test the configuration \{#step-2-test-the-configuration}

<TimelineWrapper>
<TimelineStep>

### Create a tenant with the key coke \{#create-a-tenant-with-the-key-coke}

Create a tenant with the key `coke`:

```json
{
  "key": "coke",
  "name": "Coke"
}
```

</TimelineStep>
<TimelineStep>

### Create a user with the admin role and a time_based_groups value \{#create-a-user-with-role--time_based_groups-value}

Create a user, assign the user the `admin` role, and set the `time_based_groups` user attribute. The following value gives the user a temporary admin entry in the `default` tenant and another in the `coke` tenant, each with its own expiration time:

```json
"time_based_groups": [
  {
    "role": "admin",
    "tenant": "default",
    "expires": 1733256879832
  },
  {
    "role": "admin",
    "tenant": "coke",
    "expires": 1733861761081
  }
]
```

:::info Time format
`expires` is a Unix timestamp in milliseconds. Pass `current_time` in `permit.check()` as a user attribute, in the same format.
:::

</TimelineStep>
<TimelineStep>

### Run permit.check() \{#run-permit-check}

Run a check for the user in the `coke` tenant. In the resource object, set `type` to the key of your resource (`internal_api`). The call passes the current time as the `current_time` user attribute:

```javascript
const permitted = await permit.check(
  // User object
  {
    key: "george@test.com",
    attributes: {
      current_time: new Date().getTime(),
    },
  },
  // Action
  "patch",
  // Resource
  {
    type: "internal_api",
    tenant: "coke",
  }
);
```

The expected results:

| Condition at check time | Result |
|---|---|
| The `coke` entry's `expires` is later than the current time | `true` |
| The `coke` entry's `expires` is earlier than the current time | `false` |
| The user has no `time_based_groups` entry for the tenant of the check | `false` |

To test each case, change the `expires` values in `time_based_groups` and run the check again. The timestamps in the example are in the past, so set them to a future time to get `true`.

:::tip Set expiration times from your application
In production, update `time_based_groups` with the Permit API when you grant temporary access, and set `expires` to the current time plus the access duration.
:::

</TimelineStep>
</TimelineWrapper>
